# Learnings

Hard-won facts from folded changes. One dated line each.

- **2026-09-20 / mjolnir.toml:** Unknown keys are ignored (HTTP-style), not rejected. A committed `[site]` or future key must load on an older `mj`. Required-field checks still catch hyphen typos (`start-command` → `start_command is required`). Closed key sets break mixed-version checkouts.

- **2026-09-20 / add-honor-being:** Folding architecture after implementing landings must not import unbuilt SHALLs (Forgejo key registration, prod CORS). `add-vm-git-subkey` already put git inject in the living spec; this fold only adds being-as-device + respawn. A skill-host Opus fold spawn twice wrote `ADVISE: accept` instead of archiving — Grok repaired the honor-being fold on HEAD.

- **2026-09-10 / add-log-lsp:** pino `options.name` stamps a `name` key the first consumer's schema omitted, so `additionalProperties: false` failed every record. Envelope is library-owned. npm/bun install `optionalDependencies` by default — the win is "logger entry does not import LSP deps", not "apps do not download them".

- **2026-09-10 / add-typed-log:** Bun/Node have no AF_UNIX datagram API. Host syslog ingest is UDP (loopback / `10.200.0.1`), not unix `/dev/log`. Guest forwarder ≠ host ch2 registration. Fold living `typed-log` only after emit+ingest landed.

- **2026-08-25 / add-host-sidecar-redis:** Live `rclone` of Redis 7 `appendonlydir` is not restore-safe (torn incr). `redis-cli --rdb` is consistent as RDB, but `appendonly yes` loads AOF on start and ignores RDB; `CONFIG` was renamed empty so restore cannot flip AOF off. Host timer is stop → copy `/var/lib/mjolnir/redis/` → start. `mix mjolnir.redis.ensure` must not `app.start` (a second OTP app on the live host). Mix task module is `Mjolnir.Redis.Ensure`. No `just deploy-redis`.

- **2026-08-22 / add-mailbox-durable-accept:** Forge.Store tmp+`:file.sync`+rename does not fsync the parent directory. On macOS `:file.open(dir, [:raw, :read])` is `:eisdir`; use `[:raw, :read, :directory]`. A ledger whose 200 means crash-safe accept needs both. Exclusive `:file.make_link` is the same-id TOCTOU fix, not stat-then-write.
- **2026-08-16 / add-buzz-local-client:** Folding an architecture-plus-one-slice change must not import unimplemented SHALLs into `openspec/specs/`. Built truth is fail-closed `Mjolnir.Admit` plus `:never` refuses `DormantRegistry`; leftover SHALLs went to PENDING `add-buzz-local-runtime`.
- **2026-08-16 / add-buzz-local-client:** The I5 wake hole was `DormantRegistry` thaw on any `deliver_message`, not Reconcile — `restart_policy: never` already finalizes a stranded record.
- **2026-08-16 / add-buzz-local-client:** Same-family advise cannot sole-accept (ADR-005). Grok authored the ADR; Fable + Sol had to accept.
- **2026-08-17 / mjolnir-1pe:** SecretStore's envelope API cannot hold an unsigned nsec — `_opaque/vms/<id>/` is the store namespace. Guest `inject_identity` is in-tree; a live body still needs `just deploy --agent`. systemd `EnvironmentFile` wants `KEY=value` (no `export`) and `0640 root:agent`, not `0600`.
- **2026-08-17 / add-blob-store:** First draft named MinIO as the provider. Advise send-back: three layers (address / B2 canonical / working-set+transmit). We are not doing MinIO — not v1, not a later cache.
- **2026-08-17 / add-blob-api:** `recrypt-storage::put_with_outboard` does not hash-check (`s3.rs:217–248`); the door wraps it. Recrypt does not compile on macOS, so the door is a thin sidecar, not recrypt-core.
- **2026-08-17 / add-blob-client:** `BLOB_DOOR_URL` empty at boot so the public site still starts; put/get fail closed. Never put `B2_*` in the Taskmaster env.
- **2026-08-18 / add-web-pty-edge:** xibu dashboard and ttyd 1–3 run as root, so a dedicated `devterm4` user cannot hide `token.json` from the node app — only from `www-data`. Isolation from “the dashboard uid” is theater until node drops root.
- **2026-08-18 / add-web-pty-edge:** nginx on xibu injects ttyd Basic (same as `/devterm3`); the browser prompt is not the gate. `curl https://127.0.0.1/devterm4/` without `Host: dreamballz.com` hits the default site (Express 404), not the ttyd location.
- **2026-08-19 / add-host-sidecar-tenant:** Guest TCP to `10.200.0.1:5432` is INPUT (TAP), not FORWARD — ufw/iptables must allow overlay→hotel or a valid secret still black-holes. Dummy (not lo) so TAP `/32` guests can ARP the bind. ADR number is 0005; 0004 is web-pty-edge.
- **2026-08-27 / compute-fabric kernel:** One daemon (no community edition). Homelab gets the π-machine. Money is official Registry / ferry / hosted matching (guild tag), not a NIF or a worse OSS scheduler. Resource = claims on capacity. Path test: no speculative asset *in spawn/repair/own-box cluster*. Private kernel: `~/work/Mirror/strategy/compute-fabric-2026-08-27.md`. Do not put investor instruments in this repo.
- **2026-08-22 / github-forgejo-mirror:** Forgejo v15 cannot convert an existing repo into a pull-mirror — only New Migration with “This repository will be a mirror.” identikey/mjolnir already existed, so a host timer fetches GitHub and pushes `refs/heads/*` + `refs/tags/*` over `127.0.0.1:3000` so receive-pack (and Actions) fire. `git push --mirror` also sends GitHub `refs/pull/*`, which Forgejo rejects as hidden. Disk-fetching into `/var/lib/forgejo/data/repositories/` would skip receive-pack.
- **2026-08-24 / edgebox rec:** Blob door replaces MinIO for any appliance, not just Mjolnir guests. `recrypt-server` also defaults to :7222 — guest-local server vs host door is two namespaces; bare metal must not bind both to one port. Storage-auth on the box is the AGPL server process, not a crate link into identikey-core.
- **2026-08-19 / add-blob-door-overlay:** Guest TCP to `10.200.0.1:7222` is the same INPUT trap as 5432. rclone's B2 key is bucket-scoped to `mimir-backups` (no manageKeys) so the door stores `blob/b3/` in that bucket; the door has no DELETE even if the key can. The door rides `just deploy` (`scripts/deploy.sh` → `install-blob-door.sh`); do not add a just verb per sidecar. Non-interactive SSH has no cargo — the install script puts `~/.cargo/bin` on PATH. Elixir restart is required for `blob_door_url` inject (`vm.ex`); the door unit itself must not restart Elixir.
- **2026-09-20 / recrypt Blake3:** `Sites.Crypto.blake3_hash/1` is real Blake3 via `mjolnir-b3` (same crate as the door). Recrypt cutover is `MJOLNIR_RECRYPT_STORAGE_URL=http://10.200.0.1:7222` in `/etc/mjolnir/env` + Elixir restart. Temp files for `mjolnir-b3` must land under a `ReadWritePaths` dir (`:socket_dir`, `/tmp/mjolnir`), not `/tmp`.
- **2026-09-21 / identikey fp Blake3:** `IdentiKey.fingerprint/1` is Blake3 of the raw ED25519 pubkey (same `blake3_hash_base58` as content hashes). Live SHA-256-stub fps were reminted (mjolnir-61a2). New fp ≠ old fp, so `_index/aliases/<fqdn>` refuses the PUT (`alias_already_claimed`) — rewrite the index files as root after republish. Same-key remint still needs that rewrite. Park + intentional keys were not on disk; reminted. wtnf CI token is bound to the old SHA-256 fp. Holder fps stay auth-challenge v1 §5 (`Blake3(dcbor({alg,key}))`).
- **2026-09-20 / add-identikey-being-client:** `identikey-oidc::Client::new` defaults to **pairwise**, and `client_from_spec` never set `subject_type` — an env-registered client silently gets `KDF(salt, xid, sector)` as `sub`, which is not the 64-hex XID `authorize_vm` compares to `owner_id`. Any Mjolnir-side OIDC client must be registered `subject_type=public` explicitly. identikey-core also has no device_code grant (no RFC 8628), so the Keycloak device-code login could not be ported — same-origin `/term` is a 302 to `/authorize` plus a callback on the API origin. Issuer cutover strands existing VMs whose `owner_id` is a Keycloak UUID `sub`: they no longer match an XID token.

- **2026-09-19 / add-honor-dev-preview:** `bun run dev --host` alone is a **403**, not a 200, on a ticket URL — Vite 6 rejects an unknown `Host`, and `0.0.0.0` only wins the bind, not the header check. `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS=.vm.worldtree.network` (exported *inside* the tmux pane; `mj exec` env does not persist) is what makes first paint work. Expect this for every dev server put behind a ticket URL. `XAI_API_KEY` tmpfs-only is enforced only against the storefront `.env` — grok's config dir and shell history are unguarded before `mj snapshot create`.

- **2026-09-20 / add-vm-git-subkey:** One opaque blob is not enough. Revoking the *old* device on respawn needs `xid` + identikey `credential_id` + pubkey under the old `vm_id`, so metadata lives in a second blob (`git_signing_device`) — otherwise revoke either copies private bytes across `vm_id`s or cannot name what to revoke. `Identity.env_entries/1` is a Buzz-specific env map, not a generic inject: git signing needed its own vsock `inject_file` to a *fixed* guest path (`/run/mjolnir/git_signing_key`, tmpfs, 0600) so `git config user.signingkey` survives a key rotation untouched. Revoke order is Forgejo → `revoke_device` → opaque, but step 1 is an unwired hook until `add-honor-git-remote`, so a respawn today leaves a live Forgejo key with no identikey row — the inverse of the intended failure mode.

- **2026-09-20 / add-buzz-relay:** "`mj snapshot create` is the backup verb" and `secrets_mode: managed` do not compose. Escrow is keyed by `vm_id`, `VM.spawn/1` mints a fresh UUID even for `--snapshot`, a real kill deletes the escrow, and the guest refuses `init` over an existing `secrets.luks` — so a restored hive dies at `secrets_unlock_failed` with the relay unit never starting. Root must copy `/var/lib/mjolnir/escrow/<old_id>` to `<new_id>` before the spawn (`docs/runbooks/buzz-relay-restore.md`); `docs/secrets-architecture.md`'s "clone rootfs from snapshot → escrow HIT" arrow is same-id dormancy wake only. Same pass re-confirmed the 2026-08-17 note from the other side: the agent writes `export KEY='v'` at `0640 root:agent`, which `EnvironmentFile=` silently drops — units must start `/bin/sh -lc` as root.

- **2026-09-21 / add-sites-fallback:** `SecretStore`'s signature check re-derives canonical bytes by *sniffing fields* (`head_record?` / `manifest?` / `alias_record?` in `canonical_bytes_without_sig/2`) — a fourth record type is not recognized by adding a key. `sites/<name>/fallback` therefore verifies in `Mjolnir.Sites.FallbackPolicy.verify/1` at the router before the store ever sees it; routing policy through the generic envelope path would silently fail to verify. Same shape on the serving side: the policy is a plain-text sibling of `current`, outside the tree `ServeDir` serves, so a snapshot file literally named `fallback` stays an ordinary asset and `GET /fallback` runs the miss order instead of leaking the policy.
