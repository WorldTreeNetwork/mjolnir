## Boundary and proposed decisions

Protect payloads, catalogs and semantic names from relay/host processes; keep admission tokens separate from client content credentials. The browser origin is trusted for this iteration (Duke, 2026-11-23). Non-extractable HKDF/AES keys stop export, not use: both browsers derive media key bytes and decrypt with a retained handle (`crypto-browsers.log`), and plaintext media is page data. This does not defend against replacement page code or secret strings before import. An owner creating later invitations must retain raw secret/link material or generate invites up front; handle-only guests do not imply handle-only owners.

1. **B1 correction.** Context is `mjolnir-call/v1/<owner>/<room>/<label>`, opaque is `path("call")`. Shared room secret/kid, separate credentials per publisher label. Old room-context/path(label) failed when a relay changed both segments: claim 5a decrypted alice as bob; 5b with label context returns Authentication (`b1-relabel.log`, regression `spikes/rust/tests/b1_relabel.rs`). The old test of unequal path strings did not test transplant resistance. Shared-secret holders remain capable of forgery if the relay colludes.
2. **Profile-owned layout and instance selection.** `01-wip` uses `t/<owner>/<room>/<label>/<opaque>/<epoch>`, default wire moq-lite-06. Select greatest active canonical UUIDv7 epoch and keep a per-credential/label high-water mark; never automatically return to an older one. First-live-match selected stale publication (complete finding F2; `b-rekey.log` is the later manifest diagnosis). This rule is a contract choice, with its no-rollback regression still owed, not a measured freshness guarantee. A relay can withhold the latest or replay to a fresh reader. Existing epoch-in-path ASK remains open. Re-decide at successor profile, which deletes Epoch ordering.
3. **Navigated links have persistent secrets.** replaceState removes only the current URL/session-history entry. Both browsers persist the full invite/key/token before page scripts, Chromium also in session files (`b3c-history-chromium.log`, `b3c-history-firefox.log`). No client script can promise erasure. Duke must accept that and require a security note, or choose another delivery; recommend paste into an already-open page. Same-document hashchange persistence was not tested. Encryption constrains the content credential, not token delivery. A token included in any link goes only to relay admission.
4. **One bridge surface.** Use protected `bridge.tracks`, mapping semantic names to `{timescale, maxAgeMs, priority}`, with complete snapshots on changes and every second, plus duplicate-name suppression. Both bridges implement this contract; metadata agrees with TRACK_INFO. The complete spike required this to recover audio after rekey and avoid JS name reuse; it demonstrated both directions (`b5-cross-chromium.log`, `b5-cross-firefox.log`). Catalog-only discovery is simpler in the long term but unrun here; it is not selected. This is an application manifest, not an upstream format claim, and it is revisited when native trait wrappers remove bridges. Real LocalBroadcast/RemoteBroadcast media works without a fork (`b-native.log`). Browser must send H.264 for native readers; Firefox H.264→native remains unrun.
5. **Removal is immediate publisher retirement, not token revocation.** Generate greater kid/fresh secret; each remaining publisher announces new generation then immediately stops old-key encryption and finishes/closes old publication without waiting for readers. Readers may retain old credentials read-only. Remaining clients already given the new credential recovered after ~190 ms stall in Chromium runs 1/2 before their driver watchdog, with old buffered tails ~0.5–0.7 s (`b-rekey-run1.log`, `b-rekey-run2.log`); no timing guarantee follows. Loaded run 3 needs idle repeat. Until an open-page handoff is chosen and tested, link guests get replacement per-guest invites and rejoin; fixture injection is not distribution proof. Removal is only complete after every remaining publisher retires its old generation.
6. **Admission limits persist.** Only owner can mint; link token lives to exp, normally ≤3600 s from issuance under configurable ceiling; link guest cannot renew; forwarding shares one label. `mjolnir-rurh.5` owns messaging, per-guest links, replacement flow and longer-call policy under existing room-auth; no delegated-invite change is named. WebTransport mid-media expiry/reconnect and bare Iroh close are measured (`b-expiry.log`); Iroh publisher expiry with media is not. A live reconnect can preserve original generation/counters, but a replacement process must mint anew.
7. **Keep a thin experimental adapter.** Both languages pin moq `4a6f522483168ace392718d68b58a402533c897d`; native pins iroh-live `747b1bd0567d2f6b019a89633c04e6561ccac460`. Profile, path/manifest and invite parsing form the Mjolnir seam; no relay fork or custom cipher. Default-on profile remains Duke's choice. Shared vectors already agreed in the review (JS 9/205, Rust 51); complete run adds JS 61 tests (`js-unit.log`), tamper interop (`b-interop.log`) and real relay mixed-media directions. Rust vectors were not re-run by the complete spike.
8. **Per-process-instance producing state.** New publisher process mints a new producing generation. A live reconnect may keep the original generation only with intact claims/counters. Do not restore/reset producing state; guest constraints below belong to the future guest feature, not this spec's shipped behavior.
9. **Test-only relay capture.** Acceptance uses an in-process harness built from the same mjolnir-relay crate and its real admission/Iroh handlers. Keylog exists only in the harness; no production capture or shipped runtime keylog switch. Plaintext, passive encrypted and token-only captures are separate (`capture-*-results.json`). Test injected media content (VP8 frames/headers and 440 Hz audio correlation) and semantic markers, not decoder exit status: Opus decodes ciphertext into noise. Chromium capture works; Firefox capture and shipped-adapter repeat remain owed.

## Upstream status and migration

At `4a6f52248`, `quest/m5/e2ee/README.md:11` calls E2EE **“not ready yet”**. `moq-e2ee-01` is decided 2026-11-16 and not landed at the pin (the review's 2026-11-24 remote check also found it absent; no current-remote claim is made here). `rs/moq-e2ee/Cargo.toml:13` points at the format work.

`quest/m3/e2ee-format.md:25-49,54-82,109-130` changes broadcast-name binding, one key per group, public per-track entries and moq-net trait-compatible wrappers, Epoch→Instance without UUIDv7 ordering, and no compression in the profile. `quest/m5/e2ee/README.md:38-39` closes/supersedes the mux bridge; `quest/m5/e2ee/browser.md:11` plans direct encrypted-broadcast support in publish/watch. Do not treat planned APIs as landed.

WIP has per-track-key limits of 2^36 plaintext bytes / 2^24 operations, counting failed opens; a relay can spend a consumer's budget. Producer Exhausted requires a new generation, not reset state. A reader may rebind the epoch with bounded retry; repeated exhaustion must surface as a failure, with no plaintext fallback. JS duplicate-name creation differs from Rust claim resumption, so both bridges follow the stricter duplicate rule. Profile upgrades change keys/names/paths, require coordinated endpoint upgrades/vectors and re-decide layout/reader rule/manifest; they require no relay change. Recommend WIP for development and prefer finished 01 for default-on if available after validation; ASK remains open.

## Active relay and permanent product consequences

| Relay power | Boundary |
|---|---|
| Drop, delay, reorder, truncate groups after any frame | Availability and completeness are not authenticated (pinned draft lines 329, 372–373) |
| Replay same-instance ciphertext to a new/late reader; withhold newer instances/credentials | No proof of newest content; D2 cannot force disclosure |
| Change frame timestamps | Not authenticated: 124→999 ms decrypts (`b-interop.log`) |
| Spend consuming AEAD budget via failed opens | WIP key limits, upstream format audit lines 64–70 |
| Help token-only readers fetch physical ciphertext | All announcements and requested physical names visible (`capture-tokenonly.log`) |
| Transplant across label contexts without a secret | Refused by B1 fix (`b1-relabel.log`); a colluding holder removes this protection |
| Read/forge payload, splice across cryptographic context/kid/epoch/track/group/frame identity | AEAD refuses covered tamper cases (`b-interop.log`); timestamps are an explicit exception |

Clear metadata: owner/room/label, opaque and UUIDv7 start time, physical names/count/kind/length class, group/frame structure, public timestamps, sizes, timing. Semantic probes by a token-only client can appear verbatim in transport even though publishers hide semantic names. No padding or traffic-analysis protection.

The platform cannot record, transcode, transcribe, compose or preview protected calls while it lacks the credential; those operations must terminate at a credential-holding endpoint. A recorder inside a Mjolnir guest puts the key inside the operator host's boundary. Relay bandwidth is still central egress; future untrusted peer fan-out is enabled in principle, not shipped.

Not chosen: SFrame with MLS offers forward secrecy, post-compromise recovery and membership removal, but needs member identity keys and a delivery service absent at this pin. A future MLS exporter could supply `{kid, secret}` per epoch through the credential seam; those group-security properties are not claimed now.

## Future guest-publisher constraint (not implemented by this capability)

Any credential holder inside a Mjolnir guest, publisher or reader, is inside the host's trust boundary: memory snapshots write guest memory to host disk. A future guest-publisher change must support memory thaw only for captures with CONFIG_VMGENID and verified guest observation of the changed generation id (`openspec/specs/vm-freeze/spec.md`); legacy captures cannot run a guest publisher. Stop encryption across thaw, wait until the guest observes the generation change and kernel randomness has been reseeded after thaw, then mint the new epoch/generation from that fresh randomness before any frame. Do not draw it from copied userspace PRNG state; kernel reseed alone does not reset that state. Missing observation must fail closed, never publish another old-generation frame. This is a constraint on that future change and its tests, not an unbuilt guest-thaw SHALL in the living encryption spec.
