## Boundary and proposed decisions

Protect payloads, catalogs and semantic names from relay/host processes; keep admission tokens separate from client content credentials. The browser origin is trusted for this iteration (Duke, 2026-11-23). Non-extractable HKDF/AES keys stop export, not use: both browsers derive media key bytes and decrypt with a retained handle (`crypto-browsers.log`), and plaintext media is page data. This does not defend against replacement page code or secret strings before import. Guest handles live in page memory; the owner's later-invite copy lives only in a private page-memory closure, not persistent application storage. Leave/call-end/replacement discards obsolete references (except permitted consuming handles); reload loses both and asks for the invite again without joining. Handle-only guests do not imply handle-only owners, and garbage collection cannot wipe parser strings or browser history.

1. **B1 correction.** Context is `mjolnir-call/v1/<owner>/<room>/<label>`, opaque is `path("call")`. Shared room secret/kid, separate credentials per publisher label. Old room-context/path(label) failed when a relay changed both segments: claim 5a decrypted alice as bob; 5b with label context returns Authentication (`b1-relabel.log`, regression `spikes/rust/tests/b1_relabel.rs`). The old test of unequal path strings did not test transplant resistance. Shared-secret holders remain capable of forgery if the relay colludes.
2. **Authenticated instance selection (unrun).** WIP path remains `t/<owner>/<room>/<label>/<opaque>/<epoch>`. Try candidates greatest first, but only a successfully authenticated frame accepts an instance and advances the greatest accepted epoch per credential/kid/label. Failed authentication or 1500 ms with no authentic frame falls through to a candidate at or above the mark, keeping any accepted stream playing. At most 12 new candidates per label per rolling minute, one at a time, no immediate retry of a failed epoch; exhaustion reports retryable unavailability without clearing accepted state. Mark is page memory only, reset on reload; no automatic below-mark rendering. A publisher watches its label; another greater authenticating instance stops its publication with “you joined somewhere else”; explicit resume mints anew. This repairs second-device switching on sane clocks, but a fast-clock accepted epoch can outlive correction: show “newer stream expected, older one present”, with manual-switch UX in mjolnir-rurh.5. The browser harness ran no instance rule (`page.ts:71,86–88` takes first match); Rust `b1_relabel.rs:297` shows the forged re-mount announced and greatest, which would poison the former announcement-based mark. F2 is summary-only, not retained stale-path log evidence. All new policy tests remain C1. A relay can still hide newer content/replay to fresh readers; layout/order is re-decided at successor bump in D7, not a spec process SHALL.
3. **Navigated links have persistent secrets.** replaceState removes only the current URL/session-history entry. Both browsers persist the full invite/key/token before page scripts; Chromium also retains it in session files and segmentation_platform/ukm_db (`b3c-history-chromium.log`, `b3c-history-firefox.log`). Off-device history sync and URL-keyed metrics are unverified. Author recommends paste after validation; second reader recommends disclosed navigated links with one secret per call first, plus paste as a second entry. Both are recorded in the open ASK; Duke has not chosen either. Same-document hashchange persistence is untested. A token in any link goes only to relay admission.
4. **One versioned bridge surface.** Keep the tested v1 protected bridge.tracks map `{semantic: {timescale, maxAgeMs, priority}}`, no new envelope. It belongs to invite v=1/context mjolnir-call/v1; unsupported versions refuse. Readers cap decrypted JSON at 16 KiB/32 entries; reject duplicate keys, empty/non-string/>15 UTF-8-byte names, extra fields, wrong types and invalid metadata. Timescale is null or positive safe integer; maxAgeMs null or nonnegative finite safe integer; priority integer [-128,127]. Use authenticated manifest metadata; reject a track if relay TRACK_INFO disagrees, never replace manifest values. One-frame snapshots apply atomically only from a newer authenticated/validated group; old/duplicate groups cannot roll them back. New reader rules are unrun; the native harness used TRACK_INFO. Periodic refresh and duplicate suppression fixed missing audio/reuse; both directions ran (`b5-cross-*.log`), not all new bounds/order cases. Catalog-only remains unrun/not selected. Mixed-codec limitation is design-only: there is no native-reader presence signal, so no actionable H.264 SHALL. Chromium→native decode and WebCodecs support are logged, emitted codec is not; H.264-only native support is from source. I2 precedes any owner-set/always-H.264 codec policy in C2.
5. **Bounded retention and locally observed removal.** Replacement handoff includes greater kid/fresh secret and owner-issued canonical removedLabels. Adopting readers stop rendering/subscribing removed labels immediately, including buffered media; for each other label stop old-key reading when its first new-kid instance authenticates. Release old consuming handles per label and the old credential when no retained labels need it, or on leave/reload. Publisher announces then immediately stops all old-generation seals and finishes/closes: assert no seal after retire on the publisher, not from a subscriber's buffered tail. Owner keeps the set of labels issued replacements; completion at that client means each has an accepted/authenticated instance under new kid, removed labels excluded, missing labels pending; if reload loses that local set, completion is unknown until the owner re-establishes it, not reconstructed from announcements. Empty announcements cannot prove it; a relay can delay but cannot fabricate authentication without a holder. This does not prove old tabs stopped. Rejoin warns to close the old tab, or mjolnir-rurh.5 implements/tests a same-origin stop signal. A waiting reader loses retired publishers until delivery, potentially minutes; no old-key overlap is allowed to avoid that cost. Unloaded runs 1/2 pass both scenarios, then exit 2 because browser.close() did not return; their ~190 ms recovery and 513–722 ms tails are measurements, not bounds or seal assertions. Firefox, staggered two-publisher rekey, read-only retention and clean teardown remain unrun.
6. **Admission limits persist.** Only owner can mint; link token lives to exp, normally ≤3600 s from issuance under configurable ceiling; link guest cannot renew; forwarding shares one label. `mjolnir-rurh.5` owns messaging, per-guest links, replacement flow and longer-call policy under existing room-auth; no delegated-invite change is named. WebTransport mid-media expiry/reconnect and bare Iroh close are measured (`b-expiry.log`); Iroh publisher expiry with media is not. A live reconnect can preserve original generation/counters, but a replacement process must mint anew.
7. **Keep a thin experimental adapter.** Both languages pin moq `4a6f522483168ace392718d68b58a402533c897d`; native pins iroh-live `747b1bd0567d2f6b019a89633c04e6561ccac460`. Profile, path/manifest and invite parsing form the Mjolnir seam; no relay fork or custom cipher. Default-on profile remains Duke's choice. Shared vectors already agreed in the review (JS 9/205, Rust 51); complete run adds JS 61 tests (`js-unit.log`), tamper interop (`b-interop.log`) and real relay mixed-media directions. Rust vectors were not re-run by the complete spike.
8. **Per-process-instance producing state.** New publisher process mints a new producing generation. A live reconnect may keep the original generation only with intact claims/counters. Do not restore/reset producing state; guest constraints below belong to the future guest feature, not this spec's shipped behavior.
9. **Test-only relay capture.** Acceptance uses an in-process harness built from the same mjolnir-relay crate and its real admission/Iroh handlers. Keylog exists only in the harness; no production capture or shipped runtime keylog switch. Plaintext, passive encrypted and token-only captures are separate (`capture-*-results.json`). Test injected media content (VP8 frames/headers and 440 Hz audio correlation) and semantic markers, not decoder exit status: Opus decodes ciphertext into noise. Chromium capture works; Firefox capture and shipped-adapter repeat remain owed. A1 adds a shipped-binary negative test with MOQ_QUIC_KEYLOG and SSLKEYLOGFILE pointing at sentinels; neither may be written. A2 adds literal bridge.tracks to capture markers (not searched in retained results); A3 investigates token-only audio remote error 52 rather than declaring it understood.

## Secret lifecycle (N5; cross-call policy still an ASK)

On the owner's explicit CreateCredential/start-new-protected-call action, generate a fresh secret; later invitations share that active secret/kid until rekey or call-end. Never reuse a secret automatically from cached state. Keep raw owner material and all guest key handles in page memory only, discard on leave/end/replacement (consuming retention follows item 5), and lose it on reload: the owner/guest must re-enter an external invite or create a new credential, not restore from IndexedDB. Per-call versus intentionally re-importable standing room link is Duke's new unanswered ASK, recommendation one per call; a standing-link answer changes cross-call import policy, not storage/reload rules. External saved invites and browser history outlive this application state; ending the call does not prevent decrypting its recorded ciphertext.

## Upstream status and migration

At `4a6f52248`, `quest/m5/e2ee/README.md:11` calls E2EE **“not ready yet”**. `moq-e2ee-01` is decided 2026-11-16 and not landed at the pin (the review's 2026-11-24 remote check also found it absent; no current-remote claim is made here). `rs/moq-e2ee/Cargo.toml:13` points at the format work.

`quest/m3/e2ee-format.md:25-49,54-82,109-130` changes broadcast-name binding, one key per group, public per-track entries and moq-net trait-compatible wrappers, Epoch→Instance without UUIDv7 ordering, and no compression in the profile. `quest/m5/e2ee/README.md:38-39` closes/supersedes the mux bridge; `quest/m5/e2ee/browser.md:11` plans direct encrypted-broadcast support in publish/watch. Do not treat planned APIs as landed.

WIP has per-track-key limits of 2^36 plaintext bytes / 2^24 operations, counting failed opens; a relay can spend a consumer's budget. Producer Exhausted requires a new generation, not reset state. A reader may rebind the epoch with bounded retry; repeated exhaustion must surface as a failure, with no plaintext fallback. JS duplicate-name creation differs from Rust claim resumption, so both bridges follow the stricter duplicate rule. Profile upgrades change keys/names/paths, require coordinated endpoint upgrades/vectors and re-decide layout/reader rule/manifest; they require no relay change. Recommend WIP for development and prefer finished 01 for default-on if available after validation; ASK remains open.

## Active relay and permanent product consequences

| Relay power | Boundary |
|---|---|
| Drop, delay, reorder, truncate groups after any frame | Availability and completeness are not authenticated (pinned draft lines 329, 372–373) |
| Re-serve an earlier group in the same instance even to a reader already in the call; also replay to new/late readers or hide newer instances | Pinned profile has no grouped replay window (draft 326–329); additional bridge group-order rule below is unrun |
| Change frame timestamps | Not authenticated: 124→999 ms decrypts (`b-interop.log`) |
| Spend consuming AEAD budget via failed opens | WIP key limits, upstream format audit lines 64–70 |
| Help token-only readers fetch physical ciphertext | All announcements and requested physical names visible (`capture-tokenonly.log`) |
| Transplant across label contexts without a secret | Refused by B1 fix (`b1-relabel.log`); a colluding holder removes this protection |
| Read/forge payload, splice across cryptographic context/kid/epoch/track/group/frame identity | Payload/group/semantic/wrong-key/other-label cases are logged in b-interop.log; frame-index/kid/epoch rely on derivation and upstream vectors, with explicit C5 cases owed. Timestamps are an exception |

Choose a strict authenticated group-order rule for live readers rather than accept replay of already opened older groups: page-memory mark per protected track/kid/label/epoch, advance only on an authentic frame (and valid snapshot for manifest), never reopen offered groups at/below mark. Frames in the current group may continue until a greater group authenticates, then discard its older tail. Zero reorder allowance trades late-group playback for live forward progress. A forged high group cannot advance it; never-seen delayed content, replay after reload and retiming remain relay powers. This and manifest bounds/order/precedence have not run; C1/C2/C5 own regressions. No Hang duplicate-window behaviour is assumed.

Clear metadata: owner/room/label, opaque and UUIDv7 start time, physical names/count/kind/length class, group/frame structure, public timestamps, sizes, timing. Semantic probes by a token-only client can appear verbatim in transport even though publishers hide semantic names. No padding or traffic-analysis protection.

The platform cannot record, transcode, transcribe, compose or preview protected calls while it lacks the credential; those operations must terminate at a credential-holding endpoint. A recorder inside a Mjolnir guest puts the key inside the operator host's boundary. Relay bandwidth is still central egress; future untrusted peer fan-out is enabled in principle, not shipped.

Not chosen: SFrame with MLS offers forward secrecy, post-compromise recovery and membership removal, but needs member identity keys and a delivery service absent at this pin. A future MLS exporter could supply `{kid, secret}` per epoch through the credential seam; those group-security properties are not claimed now.

## Future guest-publisher constraint (not implemented by this capability)

Any credential holder inside a Mjolnir guest, publisher or reader, is inside the host's trust boundary: memory snapshots write guest memory to host disk. A future guest-publisher change must support memory thaw only for captures with CONFIG_VMGENID and verified guest observation of the changed generation id (`openspec/specs/vm-freeze/spec.md`); legacy captures cannot run a guest publisher. Stop encryption across thaw, wait until the guest observes the generation change and kernel randomness has been reseeded after thaw, then mint the new epoch/generation from that fresh randomness before any frame. Do not draw it from copied userspace PRNG state; kernel reseed alone does not reset that state. Missing observation must fail closed, never publish another old-generation frame. This is a constraint on that future change and its tests, not an unbuilt guest-thaw SHALL in the living encryption spec.
