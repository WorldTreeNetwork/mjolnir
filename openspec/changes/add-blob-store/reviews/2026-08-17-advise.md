# advise add-blob-store

> **ADVISE:** send-back

Readers: architect, security-reviewer, critic, explore (Iroh map), plus
this synthesis. Grok authored ADR 0003 and is not the sole accept
(ADR-005). Human asked for a real Iroh contrast; that is the send-back.

Signed result: `permission: read`, `disposition: task-red`.

Banner stays `ACTIVE BUILD`. Do not spawn MinIO. Do not `act`.

## Verdict

Send it back. The store *shape* is right. The provider *technology*
is not decided.

Keep: Blake3 of stored bytes; recrypt `blob/b3/{base58}` + `.obao`;
B2 (or an equivalent object store) is the copy that counts; guest is
not the backup; no `mjolnir-qwp` for this class; encryption sits
above the store; Taskmaster SQLite holds hashes; consume
recrypt-storage, no third layout.

Do not keep: “a provider is a Mjolnir guest running MinIO.” That
sentence authorizes `add-minio-mesh`. The proposal said guessing
that in a spawn recipe makes the first box the architecture
(`proposal.md:17–18`). Then it guessed MinIO.

iroh-blobs is **not** a durability provider. It **is** a candidate
working-set and transmit layer on a fabric that already speaks Iroh.
Those are different jobs. The ADR fused them and waved the second
off in one line (`design.md:77–78`, `design.md:180`).

## Steelman against (keep MinIO+B2 as written)

`recrypt-storage::S3Storage` exists. B2’s API *is* S3. Sites already
copy `blob/b3/` to B2. Zero `Cargo.toml` in these trees depends on
`iroh-blobs`. Mjolnir ALPNs are shell / tcp-fwd / secret-inject;
Lightning Mesh is `iroh` + `iroh-gossip`. Recrypt already rejected
*embedding* iroh-blobs (“we use S3+HTTP”) and kept `bao-tree` for
hash interop. Taskmaster is SvelteKit; HTTP PUT to S3/B2 is the
cheap first client. iroh-blobs latest is not production quality
(n0’s banner). Destroying a wrong MinIO guest is the ADR’s own
recovery path. Compatible hashes mean a later iroh-blobs provider
does not rename objects.

That is a coherent first landing. It is not in the document as a
contrast. Until it is, advise cannot accept a spawn.

## One real tradeoff

**Independent boring durability vs native mesh transfer.**

B2 (any S3 client) gives “destroy the guest, hash still GETs” on
day one with tools this host already runs. iroh-blobs gives
verified, identity-addressed, E2E transfer on the fabric you
already operate — and **no** independent copy unless you add a
sink. One box does not do both. MinIO does not resolve that; it
only makes the working set speak S3.

A second tension: **browser/TS first consumer vs Rust/mesh later
consumers.** S3/HTTP wins the first. Iroh-blobs wins the second.
The ADR names Taskmaster first and then SHALLs the first provider
as the only provider.

## What the trees actually run

Explore + the other three agree. Citations, not vibe.

- Mjolnir Iroh is **transport**. Guest binds `Endpoint::builder(presets::N0)`
  and four ALPNs — shell, shell v2, TCP forward, secret inject
  (`native/mjolnir_guest_agent/src/iroh.rs:56–70`;
  `native/mjolnir_protocol/src/lib.rs:17–33`). No blobs ALPN.
  Gateway HTTP fallthrough uses `TCP_FWD_ALPN`
  (`native/mjolnir_gateway/src/main.rs`). Tickets are
  `EndpointAddr` / z32 node ids (`lib/mjolnir/ticket.ex`), not
  `iroh_blobs::BlobTicket`. `native/Cargo.lock` has `iroh 1.0.0`
  and zero `iroh-blobs`.
- Sites already store `blob/b3/{hash}` + `.obao` on the host
  (`lib/mjolnir/sites/store.ex`) and rclone-copy that tree to B2
  (`scripts/backup-sites-b2.sh:8–14`). Serve path can ride Iroh
  TCP-fwd; the bytes are not in iroh-blobs.
- Lightning Mesh: `iroh = "1.0"`, `iroh-gossip = "0.101"`, no
  `iroh-blobs` (`Cargo.toml:14–16`). Doctrine: “iroh is the
  identity/addressing layer, IP is access plumbing”
  (`docs/network-coordination/network-architecture.md:366–379`).
  LAN is `RelayMode::Disabled`; internet default is n0 Staging;
  `--relay` is the sovereignty hatch
  (`mjolnir-meshd.rs:6979–7055`).
- Recrypt chose `bao-tree`, not `iroh-blobs`, so hashes stay
  bit-identical without taking iroh’s QUIC stack
  (`docs/plans/2026-04-06-bao-streaming-and-storage-simplification.md:85–94`).
  `recrypt-storage` backends are memory, local, S3 — no iroh
  (`src/lib.rs`).

iroh-blobs itself (n0 docs, not in these trees): request/response
transfer over iroh QUIC plus a local `MemStore` / `FsStore`.
Verified streaming, range GET, resume, multi-source downloader.
No B2 sink. Latest crate banner: not production quality.

## Relays

Lightning Mesh’s “handshake only, never the data plane”
(`network-architecture.md:333–334`,
`relay-pinning-decision.md:46–51`) is **too strong**. Same repo’s
code: connect returns over the *relay* first; hole-punch to
direct is async; relay-only “forwards unreliable datagrams
best-effort and drops heavily under load”
(`mjolnir-meshd.rs:732–736`, `6826–6845`). Mjolnir’s guide is
the honest sentence: relays packets when direct is impossible;
does **not** decrypt QUIC
(`docs/security/iroh-connectivity-guide.md:41–51`).

So: a relay is not a confidentiality party. It **is** metadata +
NAT-hard availability. For a GiB blob GET that never hole-punches,
the relay forwards ciphertext for the session. “Relatively
minimal” is true for *content*. False as “bulk never touches a
relay.”

E2E QUIC hides bytes from the relay and the ISP. It does not hide
bytes from the peer that stores them. Encryption-above-the-store
is still required if MinIO, B2, or an iroh-blobs peer is the
holder.

## “S3 is less needed”

That argument kills MinIO-as-the-client-contract (aws-sdk gravity,
“don’t write a protocol”). It does **not** kill B2-as-canonical:
B2’s API is S3-shaped. An agent can write a thin PUT. Sites
already said to point `S3Storage` at a B2 endpoint with no MinIO
(`docs/plans/initiatives/identikey-sites.md:201–205`).

So B2-direct is a real v1: recrypt layout on B2, optional local
cache, Taskmaster HTTP. MinIO is then a cache you have not
justified. iroh-blobs is a mesh transmit / working-set you have
not scheduled.

## Findings (block accept)

1. **iroh-blobs was waved off.** Compatible addresses are why a
   later provider *can* land, not why the first must be MinIO.
   Recrypt’s primary storage rationale is backend agility
   including an iroh-blobs peer network
   (`recrypt/docs/storage-design.md:43–58`). The ADR never cites
   the fabric it already runs.
2. **“Each provider is MinIO” over-locks.** Spec SHALLs a MinIO
   guest and a MinIO B2 remote (`spec.md:26–61`). A second
   provider becomes a second MinIO.
3. **`accepted ⇒ on B2` vs ILM/replicate.** MinIO ILM is delayed
   by design; bucket replication is async. Neither is “ack after
   B2 has the bytes” (`design.md:35–38`, `185–186` vs
   `spec.md:27–29`). Gateway-to-B2 mode is gone (~2022).
4. **Hash-refuse SHALL sits on “the provider.”** Raw S3 will
   accept any bytes at any key. `S3Storage::put` checks;
   `put_with_outboard` (the bao API the ADR names) does **not**
   (`recrypt-storage/src/s3.rs:122–130` vs `217–248`).
5. **Store vs transport conflated.** “We do not speak iroh”
   (`design.md:77–78`) reads as no Iroh on the put/get path
   *ever*. The existing Iroh is transport. iroh-blobs would be
   new store work. The human’s “we already use Iroh” is true for
   transport cost already paid, false as “iroh-blobs is free.”

## What is solid

- Address = Blake3 of stored bytes; layout matches recrypt and Sites.
- Dedup is identity of stored bytes; no convergent encryption.
- Store untrusted for confidentiality; personal+PRE or Guild-Key above.
- Guest is not the durability story; FS-snapshot backup off for this class.
- Taskmaster SQLite holds hashes; ready stays derived.
- Bazaar living specs stay stack-free.
- Change slicing (shape here; spawn / client / encrypt later) is right
  *if* spawn is no longer implied to be MinIO.

## Implementer gaps (after the amend)

- Name the B2 sink as its own mechanism (direct `S3Storage` or
  write-through). Not “MinIO’s S3-compatible remote.”
- `.obao` vs iroh-blobs `.obao4`.
- `ProviderIndex` URL grammar: `https://…` vs iroh ticket.
- Streaming: recrypt `Vec<u8>` vs “store must not buffer.”
- Relay policy if a storage guest speaks Iroh for bulk.
- Browser/TS path is HTTP to the store, not WASM iroh-blobs.
- Sites.Crypto Blake3 is still a SHA-256 stub — do not hash through it
  (`lib/mjolnir/sites/crypto.ex:21–30`).

## What the amend must do

Rewrite Decision 1 as three sentences:

1. Canonical copy is B2 (or equivalent object store). Accepted ⇒
   that copy exists. Ack is HeadObject/GET on B2, not ILM hope.
2. Working set is a disposable cache. Candidates: B2-direct (no
   extra VM), `LocalFileStorage`, MinIO, iroh-blobs `FsStore`.
   First landing is chosen in the table, not by defining “provider.”
3. Transmit for mesh peers may be Iroh (already paid). First
   Taskmaster client is HTTP(S) to B2 or the cache. E2E is
   transmit, not store confidentiality.

Replace the iroh-blobs one-liner with the contrast table (MinIO
guest + B2 remote | iroh-blobs + B2 drain | B2-direct). Soften
spec SHALLs that name MinIO. Move hash-refuse onto the put path.
Then re-advise.

Recommended first landing after that rewrite (not a SHALL today):
**B2-direct + recrypt layout**, Iroh-blobs as a later working-set
/ transmit provider. MinIO only if someone still wants an S3
daemon in front of an S3 API.

## Recommended shape (not accepted — for the amend)

```
put/get (Taskmaster HTTP) ──► B2  (canonical, recrypt keys)
                         \► optional local cache

mesh peers ── Iroh QUIC (existing) ──► iroh-blobs FsStore ── drain ──► B2
```

Same hash. Same `.obao` (once the suffix is pinned). Same
encryption-above-the-store. No MinIO required for the durability
invariant this ADR exists to buy.
