# advise add-web-pty-edge

> **ADVISE:** accept-with-nits

Reader: Claude-family critic (independent). Grok 4.6 authored ADR 0004
and is not the sole accept (ADR-005). Architecture-only; no `act`, no
fold, no banner flip.

Signed result: `permission: read`, `disposition: pass`.

## Verdict

Accept with nits. Design A is the right landing: a trusted box runs
`mj connect` against the existing authenticated PTY WebSocket; the
browser never holds the Mjolnir JWT; Mjolnir does not grow a tokenless
socket. Every cited code claim checked out. Accepting this is a permit
to brief `nod-devterm4-stand`, not a permit to change `PtyHandler` or
punch a hole in `pty:connect`.

Banner stays `ACTIVE BUILD`. Fold still waits on the brief.

Nits do not owe boxes on `tasks.md`. They go to the brief or stay as
wording.

## Steelman against (pick Design B)

A dedicated WS-to-WS proxy is the cleaner hop. Browser xterm already
speaks Mjolnir's wire (`priv/term/index.html:87–116`: same-origin
`WebSocket` to `/api/vms/:id/pty`, binary I/O, text resize). A tiny
local process would add `Authorization: Bearer` and stop. One PTY, no
ttyd, no double resize, no host tmux wrapping `mj` in raw mode.

Plan 29 forbids proxying ttyd's socket *through the node app*. It does
not obviously forbid a separate unit that is not the dashboard. Closing
`mjolnir-8rr` as "not-needed" is stronger than "rejected for this
landing."

That is a coherent v2. It is not a reason to reject v1. Design B still
costs a new binary, a new compositor-inject story, and a second auth
surface next to `/devterm`–`/devterm3`. The human picked family over
hop count (`proposal.md`: Design A). The ADR records that without
pretending B is impossible.

## One real tradeoff

**Same-family double PTY vs a new single-PTY service.**

ttyd (browser ↔ local PTY) wrapping `mj connect` (raw stdin ↔
`wss://…/pty`) is one extra hop of bytes and one extra resize
propagation (SIGWINCH → text frame). Cost is real
(`connect.rs:458–499`, `pty_handler.ex:78–91`). Benefit is: compositor
JS inject keeps working, nginx basic-auth stays the browser story,
`mj` already holds the token, no Mjolnir API write, plan 29 untouched.

Design C (hosted `/term/:id`) wins the cookie path and loses the xibu
surface. Tokenless wins the dashboard's job and loses `pty:connect`.
Neither is the tradeoff this ADR is making.

## Findings (nits, not blockers)

1. **Two reattach stories sit on the page.** Decision 3 draws host
   tmux between ttyd and `mj connect` (`design.md` hop list). Open
   then says `--session main` is brief-owned. Both work; they are not
   the same. Host tmux keeps the WebSocket alive across a browser
   drop. Guest `--session` is how `/term/:id` and an in-VM agent share
   one tmux (`router.ex:539–543`, `term_page.ex:19`). Doing both is a
   double multiplexer. Brief picks one primary reattach path.

2. **Close `mjolnir-8rr` as rejected-for-v1, not never.** Task text
   (`tasks.md`) says "Design B not-needed." Fine if the close comment
   says "not this landing." Do not lose the ticket if compositor
   inject ever stops being the reason to stay on ttyd.

3. **Wording: sites tokens are 403, not "refused at Auth."**
   `design.md` says sites tokens are refused on this path. Actual:
   sites tokens take the narrow branch first (`auth.ex:53–54`,
   `token.ex:74` → `"sites:publish"`), then `require_scope(conn,
   "pty:connect")` 403s (`router.ex:545`, `authz.ex:15–28`). Same
   outcome. Do not "fix" it by special-casing PTY in `Auth`.

4. **JWT is full-scope, not `pty:connect`-only.** A valid JWT is
   overwritten to `@all_scopes` (`auth.ex:43`, `auth.ex:149–151`).
   The edge box that holds `~/.config/mjolnir/token.json`
   (`native/mjolnir_api/src/auth.rs:70–75`, `0600` at
   `auth.rs:101–103`) can spawn and kill, not just attach. Inherent
   to A and B. Not a reason to invent scoped JWTs in this change.

## What is solid

- **S2S hop is the hop that already exists.**
  `cmd_connect` builds `ws(s)://<api>/api/vms/<id>/pty[?session=]`
  and sets `Authorization: Bearer` (`connect.rs:380–415`). Binary =
  PTY I/O; text = `{"type":"resize","rows","cols"}`
  (`connect.rs:459–499`, `pty_handler.ex:78–91`). Optional
  `?session=` is validated in the router, not defaulted to `"dev"`
  (`router.ex:551–567` vs `validation.ex:47–48`).
- **Browser cannot set `Authorization` on `WebSocket`.** Stated in
  `auth.ex:16–17` and `term_page.ex:5–7`. Same-origin page stashes
  `?token=` into `mj_term` (`HttpOnly`, `Secure`, `SameSite=Lax`,
  `term_page.ex:50–56`) and opens a cookie-authenticated socket
  (`priv/term/index.html:87–89`). Foreign origin does not get that
  cookie. That is the whole problem. The ADR does not invent a
  second one.
- **Extract order matches the packet.** Bearer, then `?token=`, then
  `mj_term` (`auth.ex:82–98`; tests at `auth_test.exs:150–171`).
  Sites tokens are not returned from `extract_jwt/1`
  (`auth.ex:89`, `auth_test.exs:173–181`).
- **No tokenless public PTY.** Non-loopback, no JWT/cookie → 401
  (`auth.ex:157–174`). Loopback bypass is opt-in
  (`auth.ex:139–144`; default `false` in `config/config.exs`).
  Spec SHALL locks that. Good — fold will make punching a hole a
  spec break.
- **Design C correctly rejected as the xibu surface.** `/term/:id`
  stays (`router.ex:149–164`). It is same-origin xterm, not the
  compositor family.
- **Iroh is the wrong hop.** `mjolnir-shell/1` is P2P (`connect.rs:146–201`).
  `cmd_shell` already sends a VM UUID through the gateway WebSocket
  unless `--p2p` (`connect.rs:714–729`). xibu→API is that path.
- **Change slicing is honest.** Architecture artifacts only. First
  unit is `mjolnir-cid`. No MODIFIED of `buzz-local-client`. Living
  `web-pty-edge` waits on fold. Failed/off journeys name the actual
  defects (JWT in JS; tokenless `/pty`; node proxy).

## Implementer gaps (brief `nod-devterm4-stand`, not this change)

- **Identity:** `Policy.VM.authorize(:pty, …)` is owner-only
  (`lib/mjolnir/policy/vm.ex:36–38`). `mj login` on xibu must be
  the user who owns the pinned/spawned VM or the upgrade 404s.
- **Token file:** isolate `token.json` (already `0600`) under a
  dedicated OS user for ttyd4/`mj`. Do not let the node app read it.
  That is the distinction the ADR already uses against "JWT in the
  node process" (`design.md` alternatives table).
- **Command line:** `mj connect <uuid>` (36-char id), not a ticket.
  A ticket takes Iroh (`connect.rs:727–734`).
- **Reattach:** pick host tmux *or* `--session main` as the primary
  story. Recommend `--session main` if the in-VM agent shares the
  terminal; host tmux if the requirement is "browser drop must not
  close the WebSocket."
- **Resize:** confirm browser → ttyd winsize → (tmux) → SIGWINCH →
  `mj` text frame. That is the accepted double-PTY cost, not a
  Mjolnir bug.
- **Ops already named:** VM id (spawn vs pin), ttyd creds for #4,
  `mj login` so `mj list` is not 401.

## What would upgrade a send-back

tokenless `/pty`, (c) made Design B the v1 *through the node app*,
