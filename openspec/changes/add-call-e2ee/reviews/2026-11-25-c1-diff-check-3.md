Three further lifecycle observations:

- At 0, start and reject E1, then start E2 at the same timestamp. E1 success refuses and E2 success accepts. Ordinary failed attempts on the same epoch impose a positive bar/backoff before another start. Sequence numbers are independent of the clock (P:532).
- Accept E1000 at 1, register audio, reconcile the empty set and tick at 2. Its withdrawn record remains pinned, audio (4,0) delivers. End and tick at 2 purges the record. Reannounce and accept E1000 at 2. The retired handle refuses (5,0), and the new handle calls (4,0) duplicate. Reconciliation cannot evict a currently accepted record (P:363, P:394).
- Reconciliation withdraws announcements independently of subscription authority. Following the E1/E2 case above, an old E1 close after E2 acceptance cannot close E2. Adapter documentation should explicitly cross-reference the one permitted late probe failure in the general current-handle rule (spec.md:22,141).

R:223–256 checks monotonic epoch, acceptance return value, candidate/track/attempt/start/stamp counts, deadline upper bounds and some derived status. R:185–190 really does maintain a per-mark delivered set across handle lifetimes. Specific gaps:

- An accepted result is its own oracle for a mark move. No independently maintained live probe/session checks its identity, semantic or deadline. Stale issued subscriptions can wrongly succeed without tripping the foreign check. Track currentness is read from the implementation. Group/index inputs and authentication flag always have valid types.
- R:107 ticks before every operation and R:223 compares a partial snapshot. Clock mutation on a stale call at a later time is invisible. Private attempt order, retry timestamps, eviction floor and per-group last indices are absent. The fingerprint treats refreshed as a refusal, and the test allows any TypeError/RangeError on a valid operation if the snapshot holds.
- The repeat-report check tests one-shot handling. Deadline bounds alone cannot catch extending a timeout within the cap. No bound on bar count or transient reconciliation storage is asserted. Checking stored retry stamp count misses the actual number of replacement starts.
- Status checks cover playback, budget and the incomplete bit. Older-only is checked in one direction and without requiring any active older candidate. There is no independent check of probing, invite-needed or supersession.

Add seeded lifecycle sequences with an independent current-handle and retry-start model. Ensure the normal run reaches same-epoch replay, genuine exhaustion/expiry and rotation, asserts both directions of status facts and kills the surviving mutation. Keep the existing malformed/stale-handle and overflow generation.
