## Findings and changes required before C2

### High

**Retired track callbacks can deliver and contaminate current state.** This API gap predates the diff. Returning the existing track silently on a metadata mismatch leaves the gap in place. In S1 the E1 tracker correctly reports `duplicate` for a previously delivered `(100n, 0)`. After E2 becomes current, a delayed E1 completion looks up `audio` again and the E2 tracker returns `deliver` for that same authenticated result. E2's own `(10n, 0)` then returns `too_old` with a zero window. This refutes the refusal-only claim at the policy boundary. The authentication outcome belongs to the old consumer. The test establishes a second policy delivery decision conditional on a stale completion reaching this API. It exercises neither ciphertext transplant nor rendering. Require instance identity on registration and a current subscription check at frame/mirror commit, including callbacks that cached the tracker before an await. Invalidate delivery eligibility on retirement or replacement while preserving same-epoch marks, mirrors and budgets. Add regressions for both a fresh lookup and a cached handle after retirement. [reader-policy.ts:75](../../../../clients/call-crypto/reader-policy.ts#L75), [reader-policy.ts:337](../../../../clients/call-crypto/reader-policy.ts#L337), [reader-policy.ts:387](../../../../clients/call-crypto/reader-policy.ts#L387)

### Medium

- **The new probe-close API identifies an epoch but cannot identify a particular subscription.** In S2 the first E1 probe expires at 1500 ms and a second starts at 4500. The first probe's close at 4501 returns `true` and clears the replacement. A valid E1 manifest from the replacement at 4502 returns `false`. The same ambiguity allows a late success to satisfy a replacement probe and a delayed close to unaccept a replacement acceptance of the same epoch. Issue a distinct identity on each start, carry it through promotion and require matching identity for probe completion, refresh, accepted end and track-failure events. Obsolete events must leave a replacement subscription's acceptance and retry state alone. Test the same-epoch replacement for both pre- and post-acceptance callbacks. [reader-policy.ts:285](../../../../clients/call-crypto/reader-policy.ts#L285), [reader-policy.ts:291](../../../../clients/call-crypto/reader-policy.ts#L291), [reader-policy.ts:322](../../../../clients/call-crypto/reader-policy.ts#L322), [reader-policy.ts:365](../../../../clients/call-crypto/reader-policy.ts#L365)
- **The widened rejection path bars by announcement membership and still depends on tick order at purge.** S3a bars an announced but never-probed E1. S3b uses the same failure report for a withdrawn E1 at 4500 ms. It bars without an intermediate tick and gets ignored with a tick at 1500. Tie failures to the probe that actually performed the open. Define a bounded, deterministic late-result lifetime independent of the candidate table's purge order. Preserve the specified late-authentication bar for a valid report in that lifetime and keep a retired report from cancelling a replacement probe. Add rows for the original live-announcement case, the withdrawn case with and without an intermediate tick, and failure without a corresponding probe. [reader-policy.ts:216](../../../../clients/call-crypto/reader-policy.ts#L216), [reader-policy.ts:224](../../../../clients/call-crypto/reader-policy.ts#L224), [reader-policy.ts:350](../../../../clients/call-crypto/reader-policy.ts#L350)
- **An accepted close can burn the entire label budget through immediate reacceptance.** S4 keeps E1 continuously listed and feeds twelve successful accepts at probe starts 0, 2, …, 22 ms, each followed by a close. At 24 ms there is no playback and a newly announced higher E2 cannot be tried until 60,000 ms. A relay can cause churn if it can repeatedly close subscriptions to a still-available authentic stream. Each cycle still needs an authentic result. Once closes stop, budget lockout can persist until the oldest probe ages out. Replay state survives and the 12-probe bound holds. Pace repeated closes of the accepted epoch. Permit an immediate first reconnect if desired, then apply an epoch-local delay to repeated rapid closes that survives a single authentic manifest. Leave higher eligible epochs and the global budget independent of this delay. Document the reset rule and test both one honest reconnect and repeated rapid accepted closes while a higher announcement becomes available. [reader-policy.ts:285](../../../../clients/call-crypto/reader-policy.ts#L285), [reader-policy.ts:304](../../../../clients/call-crypto/reader-policy.ts#L304), [reader-policy.ts:337](../../../../clients/call-crypto/reader-policy.ts#L337)

### Low

- **The status API drops two facts at boundaries.** S5 has accepted playback plus a live twelfth probe. `states` is only `["ready"]` even though all twelve attempts are spent. Expose a live probe and exhaustion independently. S6 accepts and retires E1000, keeps 256 below-mark announcements, then offers E1001. The result is `full` and the label says `older_stream_only`. Re-offering can stay full indefinitely because those below-mark records never become probeable and need a withdrawal to free space. Keep the cap and either admit eligible epochs ahead of below-mark records or surface overflow as uncertainty until reconciliation. An older-only claim requires a complete view for that conclusion. Add boundary rows for both. [reader-policy.ts:156](../../../../clients/call-crypto/reader-policy.ts#L156), [reader-policy.ts:171](../../../../clients/call-crypto/reader-policy.ts#L171), [reader-policy.ts:205](../../../../clients/call-crypto/reader-policy.ts#L205), [reader-policy.ts:264](../../../../clients/call-crypto/reader-policy.ts#L264)
