## Required changes before C2

### Medium

- **Retire a track handle on terminal failure (A2).** Accept E1 at 1 ms, deliver audio `(20n, 0)` with a zero window and report failure at 2 ms. Before any replacement registration, the old handle is still current, delivers queued `(21n, 0)` and accepts a second failure report at 3 ms. An old completion can advance the retained window and change the replay decisions for the replacement. Repeated terminal notifications can also spend the six slots through one track subscription. Invalidate the handle on the first terminal failure, including the exhausted branch, and retain the mark, mirror and retry state. Give the adapter a clocked retry path after `retryAt` that does not replay the terminal callback. Test failure–frame–duplicate ordering, six distinct failed subscriptions, expiry and a replacement that still owns its mirror and mark. [reader-policy.ts:179](../../../../clients/call-crypto/reader-policy.ts#L179), [reader-policy.ts:468](../../../../clients/call-crypto/reader-policy.ts#L468), [reader-policy.ts:474](../../../../clients/call-crypto/reader-policy.ts#L474), [spec.md:24](../specs/call-e2ee/spec.md#L24)
- **Make probe rejection one-shot and subordinate to a newer same-epoch acceptance (A3/A4).** A probe started at 0 and rejected at 1 accepts a duplicate report at 59,999 and moves its expiry from 60,001 to 119,999. Separately, start A at 0, time it out at 1500, start B at 4500 and accept B at 4502. Reporting A's failure at 4501 or 4503 leaves B playing, then prevents the first reconnect when B closes at 4504. Eligibility returns at 64,501 or 64,503 respectively. A's bad result is evidence about A, and a newer authentic open of the same epoch supplies fresher evidence for retry. Retire the rejection entitlement on first report. If a newer same-epoch attempt accepts, clear an earlier attempt's bar and ignore its subsequently arriving report, including after the newer session ends. Use attempt ordering that can distinguish starts with equal clock values. Preserve S3's real late-rejection behavior where a newer same-epoch success has not occurred, including a replacement that is only probing. Specify the exception and test both callback orders. This accepts the original 60 s rule for an unsuperseded failure and closes the relay-induced hold on an already verified reconnect. [reader-policy.ts:416](../../../../clients/call-crypto/reader-policy.ts#L416), [reader-policy.ts:425](../../../../clients/call-crypto/reader-policy.ts#L425), [reader-policy.ts:455](../../../../clients/call-crypto/reader-policy.ts#L455), [spec.md:22](../specs/call-e2ee/spec.md#L22)
- **Keep candidate uncertainty through reconciliation (A5/A9).** After accepting and retiring E1000, fill the table with E1001–E1256 and offer E2000. It returns `full`. Leave E2000 active, withdraw the 256 recorded epochs and offer E1. The policy asserts a complete view and reports `older_stream_only` while E2000 remains active and unknown. Successful admission by eviction can also forget an active below-mark record without recording uncertainty. Keep the bounded table and eviction preference. Mark the view incomplete on overflow or loss of an active record. Clear it only when the adapter explicitly completes a successful reconciliation of the authoritative active set, including when that set is empty. An admission, a duplicate and a partial or overflowing reconciliation provide insufficient evidence. Replace the next-admission rule in the spec and C12 and cover both failure paths. [reader-policy.ts:225](../../../../clients/call-crypto/reader-policy.ts#L225), [reader-policy.ts:318](../../../../clients/call-crypto/reader-policy.ts#L318), [reader-policy.ts:330](../../../../clients/call-crypto/reader-policy.ts#L330), [reader-policy.test.ts:1076](../../../../clients/call-crypto/reader-policy.test.ts#L1076)
- **Require a real candidate before issuing a subscription (A10).** Start a valid E1 probe at 0. At 1 ms `nextCandidate` would return `undefined` because the probe is live. An untyped JavaScript caller passing `undefined` to `subscribe` nevertheless receives a handle, spends a budget slot and displaces E1. At 2 ms that handle accepts `bridge.tracks`, while E1's issued handle is refused. The old Boolean API already compared two undefined values on start, but its UUID validation stopped the bogus attempt from authenticating. Check that an actual eligible epoch exists before charging the budget, minting the handle or replacing a probe. Regress with a live probe and an empty or exhausted candidate set. ## Handles, pacing and contract

- Runtime identity is sound for normal issuance. Each `subscribe` returns a fresh frozen object tied to its issuing policy's weak map. Promotion retains that reference. Refresh, close and track registration use reference equality. A copied, serialized or foreign handle carries no authority (A1). The epoch descriptor is serializable and structurally assignable in TypeScript, so C2 must retain the actual reference. A private brand would let the compiler also catch accidental reconstruction. Handles are bearer references within trusted adapter code. The policy cannot prove which callback supplied a genuine handle if the adapter passes a copied reference to the wrong consumer. [reader-policy.ts:127](../../../../clients/call-crypto/reader-policy.ts#L127), [reader-policy.ts:416](../../../../clients/call-crypto/reader-policy.ts#L416), [reader-policy.ts:468](../../../../clients/call-crypto/reader-policy.ts#L468)
- Internal trackers stay private. Public standalone `GroupTracker` and `TrackHandle` construction cannot create a current policy-owned handle. Re-registering a track, ending a session and promoting a replacement invalidate earlier handles. Terminal track failure leaves a gap (A2). The adapter must apply the mirror update in the same synchronous commit as a `deliver` decision, or validate currentness again at commit if work yielded. The policy returns a decision and does not apply to the caller-owned mirror itself. [reader-policy.ts:147](../../../../clients/call-crypto/reader-policy.ts#L147), [reader-policy.ts:468](../../../../clients/call-crypto/reader-policy.ts#L468), [reader-policy.ts:497](../../../../clients/call-crypto/reader-policy.ts#L497), [spec.md:141](../specs/call-e2ee/spec.md#L141)
- A single pace record gates only the mark epoch. It cannot grow by epoch count, reduce the mark or exclude a higher eligible epoch. The delay sequence is 0, 3, 6, 12, 24, 48, 60 and 60 s in A7. A higher candidate can still await the live probe or the shared budget. A8 uses ten failed higher probes and two rapid-cycle probes, and a new higher offer then waits for a budget slot. The old E1-only S4 churn is fixed. C1 keeps one pace record and weak probe keys. With valid starts, bars are bounded by probes issued over two rolling minutes. Caps are work limits and the higher epoch still needs to authenticate. [reader-policy.ts:190](../../../../clients/call-crypto/reader-policy.ts#L190), [reader-policy.ts:283](../../../../clients/call-crypto/reader-policy.ts#L283), [reader-policy.ts:370](../../../../clients/call-crypto/reader-policy.ts#L370), [reader-policy.ts:395](../../../../clients/call-crypto/reader-policy.ts#L395)
- The [instance requirement](../specs/call-e2ee/spec.md#L22), [D2](../design.md#L42) and [ADR 0017 item 2](../../../../docs/decisions/0017-call-e2ee.md#L13) agree with the tested acceptance source, deadline, early end, timeout ladder, page-memory mark, handle identity and late-report cutoff. They need the pacing reset and obsolete/duplicate rejection semantics above. The instance requirement's next-admission wording matches the implementation, but conflicts with the [adapter section's complete-view condition](../specs/call-e2ee/spec.md#L141). The original accepted-track failure contract says the subscription ends, while the code still authorizes that handle. The adapter section should explicitly allow the bounded late report from an unsuperseded probe, and specify synchronous commit or a currentness check at the mirror. The ADR's integrated `unrun` qualification still holds. The registered cross-kid per-label budget issue remains C4 work. Manifest validation, authenticated transport indices, actual consumer reuse and real network behavior remain C2 work. [tasks.md:71](../tasks.md#L71)
