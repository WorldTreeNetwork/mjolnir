## Blind take (written before opening design.md / tasks.md)

1. PIN: RELAY_URL `wss://buzz.identikey.me` before first start — the relay seeds its tenant from `relay_url_authority` (buzz-relay `main.rs:248`) and NIP-42/98 verify `tenant.host()` + scheme-from-prefix (`bridge.rs:195`). Correct and load-bearing; keep the byte-for-byte SHALL.
2. PIN: closed membership + `BUZZ_ALLOW_NIP_OA_AUTH=true` is exactly `check_relay_membership` (`api/mod.rs:81`): agent admitted iff its NIP-OA owner is a member. Owner must be a *member* of the seeded community, not just `RELAY_OWNER_PUBKEY`.
3. REFUSE as written: "run Block's compose bundle in one VM". The guest kernel is `ch_defconfig` 6.12.8 with `# CONFIG_NETFILTER is not set` and `# CONFIG_BRIDGE is not set` (upstream ch-6.12.8; `scripts/build-kernel.sh` adds only virtio/PVH/dm-crypt). dockerd's bridge + NAT cannot start; compose's `buzz-net` bridge network cannot exist. No `@base/*` ships docker/podman. virtiofsd runs without `--xattr` (`virtiofs.ex:119-123`) so overlay2 upperdir on the rootfs is also off.
4. REFUSE the premise "`*.identikey.me` already CNAMEs to the gateway": `dig buzz.identikey.me` → CNAME `identikey.me` → A 74.207.254.179 (Linode). Only `auth.identikey.me` points at 45.76.77.97. And the only identikey.me cert on the host is `auth.identikey.me` (HTTP-01); no wildcard Origin cert exists. Steer "wildcard Origin cert" is false today.
5. PIN a named-app path that is not `mj deploy`: `mj domain set`, `mj secrets`, and `POST /api/certs/issue` all `registry_get` a `Deploy.Registry` entry, and only `Deploy.Runtime.start` (build → spawn → cutover) writes one. The change forbids casual cutover but every operator verb it cites lives behind the cutover machinery.
6. PIN the deploy-secrets injection: Orchestrator reads `<deploy_secrets_dir>/<slug>.json` and spawns `secrets_mode: :managed`; a hand-spawned VM gets no `/run/mjolnir/secrets.env`. `.env` with `BUZZ_RELAY_PRIVATE_KEY` etc. must arrive some named way, not by `mj exec` echo.
7. PIN snapshot semantics: `do_snapshot` is guest `sync` → pause → btrfs snapshot → resume (`vm.ex:3120`). Crash-consistent for PG/Redis AOF/MinIO; fine for B0, say so, and forbid `freeze` (memory snapshot) as the hive backup.
8. Living-spec fit: events on guest rootfs satisfies "Buzz events stay off the sidecar". MinIO-in-guest is not the 2026-08-17 "no MinIO" LEARNING (that was the host blob store); note it so nobody pattern-matches it into a send-back.
9. TRADEOFF: nested Docker (needs kernel rebuild + `--xattr` + a docker base image; keeps Block's bundle byte-identical, upgrades via `run.sh upgrade`) vs native systemd units in the guest (relay binary extracted from `ghcr.io/block/buzz:main`, distro Postgres 17 / Redis 7 / MinIO; no kernel work, fits `@base/` = OS roots not toolchains, but we own the service wiring and lose `run.sh add-member`). I would take native units for B0 and keep Block's `.env` contract verbatim; the compose file is documentation of the wiring, not the runtime.
10. Gateway path is fine: TLS terminates, Host preserved, `X-Forwarded-Proto: https`, raw TCP splice after headers → WebSocket upgrade passes; the relay never reads X-Forwarded (scheme comes from RELAY_URL). Port 3000 backend via `[[route]]`; DNS A/CNAME + HTTP-01 cert are two explicit steps, not assumptions.

## Steelman

**On D5.** The author is right that this is not nested KVM and that
runc works in a CH guest in principle. cgroup2, `overlay`, `fuse`,
namespaces, `veth`, seccomp are all present (`/proc/filesystems`
and the upstream `ch_defconfig` confirm it). What is missing is
narrow: `CONFIG_NETFILTER`, `CONFIG_BRIDGE`, and their NAT/iptables
children. Two honest ways through, and the design has to pick one:

- **Host-network compose overlay.** dockerd with
  `--bridge=none --iptables=false --ip-forward=false`; a
  `compose.mjolnir.yml` that sets `network_mode: host` on every
  service, re-sets `DATABASE_URL` / `REDIS_URL` / `BUZZ_S3_ENDPOINT`
  to `127.0.0.1`, and overrides `minio-init`'s entrypoint (it
  hardcodes `http://minio:9000`). Ports do not collide (3000, 8080,
  9102, 5432, 6379, 9000, 9001). Storage driver still needs an
  answer: without virtiofsd `--xattr` overlay2 cannot write
  `trusted.overlay.*` on the upperdir, so docker falls to `vfs`
  (full copies per layer — works, bloats every snapshot) unless
  `Mjolnir.VirtioFS` grows a per-VM `--xattr` option. That option is
  a Mjolnir code change; the kernel rebuild is a host-wide
  every-VM-reboot event and is *not* "no new runtime".
- **Native units.** Keep Block's `.env` contract byte for byte and
  run four systemd units: `buzz-relay` + `buzz-admin` extracted from
  `ghcr.io/block/buzz:main` (host has `skopeo`; no docker/crane
  anywhere), pgdg Postgres 17, Ubuntu's redis 7.0.15, MinIO single
  binary. Zero kernel or virtiofsd change, zero blast radius on the
  other 27 VMs, and it is the grain (`mj deploy` + unit) the design
  itself names as Mjolnir's. Cost: we own the wiring; `run.sh
  add-member` becomes `buzz-admin add-member` with `DATABASE_URL`
  in env (that is all `run.sh` does — `docker compose exec relay
  buzz-admin …`). "Four packages is a productization pass" is fair
  for B1; for B0 it is one afternoon and no host surgery.

I lean native units for B0, but the send-back does not require
that choice — it requires the design to stop asserting a path that
the running kernel refuses, and to own the blast radius of whichever
path it takes.

**On D3.** The gateway-routing doc does say `*.identikey.me` CNAMEs
to `vm.worldtree.network` and that a wildcard Origin cert is what
makes the namespace work. The author read the doc; the doc is
stale. The server's `gateway.toml` (2026-08-27 block) says
`identikey.me` TLS is HTTP-01 Let's Encrypt per host because the
worldtree ACME DNS-01 cannot issue that zone, and
`/etc/mjolnir/certs/` has only `auth.identikey.me`. DNS today
resolves every `*.identikey.me` to the apex A record on a Linode
box. So the liveness scenario as written fails at TLS handshake,
after `mj domain set` returns `cert_present: false`.

**On the bind step.** `mj deploy --name buzz-relay` is the author's
own answer to the registry gap, and it is the right instinct: the
registry row is what makes `domain set`, `secrets`, and `certs
issue` work. But `Deploy.Detector.detect/1` accepts exactly one
shape — `package.json` + `svelte.config.js` — and returns
`{:error, :unsupported_app}` for anything else. There is no
compose, shell, or "bring your own snapshot" plan, and no
`Registry` adopt endpoint. Either the change adds a minimal
build plan / adopt path (a small, reviewable Elixir change — the
registry `Entry` only enforces `app_name`, `release_snapshot`,
`updated_at`), or it deploys a trivial SvelteKit shell and then
replaces the unit inside the guest, which is exactly the "casual
cutover" hazard the change forbids because the next accidental
`mj deploy` empties the hive.

## Findings (ranked)

**F1 — D5 asserts a guest capability the kernel does not have.**
`ch_defconfig` at `ch-6.12.8` has `# CONFIG_NETFILTER is not set`
and `# CONFIG_BRIDGE is not set`; `scripts/build-kernel.sh` only
enables PVH/virtio/dm-crypt on top. `/proc/sys/net/bridge` and
`/proc/net/ip_tables_names` are absent in a live guest. virtiofsd
starts with `--cache=auto --sandbox=none` and no `--xattr`. Docker
Engine + Compose "installed in the guest" will not bring up
`buzz-net`. Required: name the path (host-network overlay +
storage-driver decision, or kernel + virtiofsd change with its
every-VM blast radius owned, or native units) and put its steps in
tasks.md. Task 1 as written cannot be checked.

**F2 — D3's DNS and TLS premises are false on the host.**
`buzz.identikey.me` → CNAME `identikey.me` → `74.207.254.179`
(Linode), not `45.76.77.97`. No wildcard cert; the apex's own
comment says HTTP-01 per host. Required: two tasks before the
liveness scenario — add the `buzz.identikey.me` record (A
`45.76.77.97` or CNAME `vm.worldtree.network`), then
`POST /api/certs/issue` (`mj cert`) which needs the DNS in place and
port 80 at the gateway. Fix `docs/gateway-routing.md` §"How to
point a name" or mark it aspirational; it will mislead the next
reader the same way.

**F3 — the named-app bootstrap has no working path.**
`Detector` is SvelteKit-only; no adopt endpoint; `mj secrets`,
`mj domain set`, `mj cert` all 404 without the registry row; deploy
secrets reach a guest only through `Deploy.Orchestrator`'s
`:managed` spawn. Required: decide between (a) a minimal Elixir
change — a `Registry` adopt/`PUT /api/apps/:app` for an existing VM
id, or a "compose/unit" build plan — and (b) an explicit one-time
`mj deploy` of a placeholder with the hive installed after, with a
guard (or at least a written rule) against redeploy. (a) is the
one that survives the "stateful, no casual cutover" SHALL.

**F4 — secrets delivery is asserted, not designed.** "inject at
spawn into the compose `.env`" is not a thing Mjolnir does today;
the `:managed` path renders `/run/mjolnir/secrets.env` (tmpfs,
`KEY=value`, `0640 root:agent` per the 2026-08-17 LEARNING). Block's
`run.sh` requires a file named `.env` in the compose dir with no
`CHANGE_ME`. Native units read `EnvironmentFile=` directly and
sidestep this; the compose path needs a unit that renders `.env`
from `secrets.env` before `run.sh start`. Say which.

**F5 — delta scenario "Owner identity … cannot be removed through
`buzz-admin`" (proposal journey step 3).** Not verified in relay
source during this pass; `run.sh remove-member` exists and takes
any pubkey. Either cite the guard or drop the claim from the
journey. Not blocking.

**F6 — snapshot wording.** "A VM snapshot *is* the hive" is true for
`mj snapshot create` (sync → pause → btrfs snapshot → resume), which
is crash-consistent. Add one line saying so and that `freeze` is not
the backup verb, so B1's `btrfs send` story starts from an honest
baseline. Not blocking.

## What would flip this to accept

- D5 rewritten to name the runtime path and its host blast radius
  (F1), with tasks that can be checked on the current kernel or
  with an explicit kernel/virtiofsd task if that path is chosen.
- Two tasks for DNS + HTTP-01 cert, and D3's premises corrected (F2).
- A named bootstrap for the registry row that does not depend on a
  SvelteKit build plan (F3), and the secrets rendering step (F4).

No change to the delta SHALLs is needed. The `RELAY_URL` byte-for-byte
requirement, closed membership + NIP-OA, guest-resident event log,
and gateway-terminated TLS all survived the blind read and the code.
