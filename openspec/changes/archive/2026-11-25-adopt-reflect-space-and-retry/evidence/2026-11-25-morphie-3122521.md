## What earlier attempts the same day found

Seven runs before this one failed, and each failure was diagnosed and fixed before the next run; nothing of them is kept but this note.

1. Behind four stalled handshakes Mjolnir's client took 7642 ms. A separate script on the same image then served it in 4–7 ms in every arrangement (stalls alone; flood, then stalls; with and without the old client), and homoiconic's client in 3–7 ms. The cause was the next item.
2. The flooding address had been added to the TAP, and later to `lo`. The TAP has no address, so Linux took that address as the source for every datagram to the guest, Mjolnir's own included: the "flood" shared Mjolnir's address. The runner now pins Mjolnir's original source on the guest's `/32` route for the flood and checks in the capture that the two addresses differ.
3. One run failed its first boot in 243 ms with `entity_name_mismatch`: readiness read the serial log while the guest was still writing `reflect: entity <name>`, and the regex accepted the cut-off line. Fixed in `Mjolnir.Unikernel.boot_outcome/3` (complete lines only) with a regression test.
4. The stall capture was empty: `tcpdump` without `--immediate-mode` lost its last buffer on SIGINT. The runner now uses `--immediate-mode`.
5. The e9a4c86 control was first timed from its own start; the 2 s cap counts from the stalls' first Initials. It is now timed from the stalls' start.
6. `mj info` takes no `--owner`; the runner reads the same record with `curl` on the operator socket.
