## Owed before act

1. **Pin the salt read contract and failure behavior.** `design.md:13` and delta lines 6-8 promise a response field without identifying its source. `lib/mjolnir/secrets/redeem.ex:66` reads only opaque `value`; `SecretStore.get_opaque/3` returns arbitrary bytes, not a value/salt record. The inspected runtime has a commitment helper but no secret salt storage/read contract. Specify where the same 32-byte salt used for the stored secret's commitment comes from, how its association with that value is maintained, and what happens for missing, malformed, or legacy value-only material. A fresh salt invented during redeem would not open an existing commitment. Keep deposit/mint implementation outside this node: define the provisioning precondition and test fixture boundary. Add acceptance for returned bytes matching that commitment and failure returning no secret. Because `prove/1` is shared with egress, state how that existing caller retains its behavior when copy-out gains salt.

2. **Make the holder-proof verification plan discriminate authorization failures.** `tasks.md:3-7` covers success and replay but could pass with insufficient holder checks. The current `test/mjolnir/secrets/redeem_test.exs` has only nonce consumption, missing-proof egress, and signing-string assertions. Specify a real challenge-to-redeem router round trip with operator shortcuts disabled and no JWT, plus wrong signer, holderless token, wrong resource/operation, modified signed fields, expired/restarted nonces, and concurrent replay. Pin the existing consume-before-proof behavior (`redeem.ex:55`): a failed proof burns that nonce and retry obtains another. Include a control showing ceremony grants no general API access. These are focused proofs of the proposed contract, not new product scope.
