## Implementation review notes

The new work is the precondition, not another cryptographic primitive. `native/mjolnir_biscuit/src/lib.rs:12` already re-exports the protocol helper, and the CLI's existing `AppendHolder` branch (`src/bin/mjolnir-biscuit.rs:158`) demonstrates parse → append → serialize. Reusing that helper after validating the source holder check satisfies the specified `Biscuit::append` mechanism without another dependency.

Recognize an actual canonical holder check and obtain its fingerprint from that check. A string containing `holder(`, a caller-supplied fingerprint, or a query with an alternative that bypasses the holder condition is not evidence of the required check. Repeated identical checks must remain usable for successive hops. Unsupported or ambiguous forms can fail closed; this change need not implement a general Datalog equivalence engine.

For the planned test task, distinguish a source missing its check from authorization missing verifier injection. Cover both, plus a wrong holder, changed resource/operation, repeated hops, and tampered or non-appendable input. Inspect the appended block to establish that exactly one check-only block was added and earlier restrictions survived. These are verification guidance for the accepted contract, not additional scope or owed architecture boxes.
