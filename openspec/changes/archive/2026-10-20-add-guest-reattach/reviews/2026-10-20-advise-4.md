## Blind take

I wrote this before opening `tasks.md`, `steer.md` or any earlier review. It is on disk in that order. The one change since is in item 3: "died on a signal" was wrong about when a scope fails. The correct version is in C2.

1. **Pin:** a per-instance namespace for the slice and scope prefix, the same way `tap_prefix` already works (`mjt-` in `config/test.exs`, mjolnir-0ut). The orphan rule stops every scope in `mjolnir-vms.slice` that has no record. A test or dev BEAM on the host has its own readable StateStore (`/tmp/mjolnir-test/state`), so starting one would stop every production guest.
2. **Pin:** startup does not unlink the API socket or the vsock UDS of a scope it attaches. `clean_stale_sockets` (cleanup.ex:94) unlinks every `.sock` and `_vsock`. Once the bound path is gone, the host cannot `CONNECT` and cannot call `vm.info`, so attach cannot work. The spec forbids the unlink only when the StateStore is unreadable.
3. **Pin:** systemd's `failed` ActiveState is a death, and the name is reclaimed before a cold resume. The single child id is reused across resumes. A failed scope stays loaded, and `systemd-run --unit` refuses a loaded name. That refusal is not "already active", so it counts toward retirement.
4. **Pin:** persist intent before signaling the scope. Today stop deletes the record. Dormancy deletes it and keeps the guest in the DormantRegistry instead (`handle_done`).
5. **Refuse:** a watcher that restarts guests, and kills keyed on a `ps` command line.
6. **Refuse:** cold resume while the unit is active. That would put two VMMs on one virtiofs rootfs.
7. **Note:** if virtiofsd dies while cloud-hypervisor lives, the scope stays active, so a guest with no root filesystem counts as alive. That is no worse than today. Health probes own it.
8. **Note:** the watcher has to capture the exit status before systemd collects the unit.
9. **Tradeoff:** with no runtime off switch, rollback means a redeploy. In return the cutover reboots the fleet once.
10. **Note:** `terminate/2` with `:shutdown` kills the hypervisor through `cleanup/2` today. Detach has to skip that call, not just the port close.

## Steelman against my take

The design is sound and I'm not proposing a different one. There is one restarter. The watcher only witnesses. systemd is the authority on liveness, and the unit name works as a structural mutex. Advise 1 through 3 drove the classification table to a fixed point, and I found no row that contradicts another. Take items 4, 5, 6 and 10 are already in the contract. Items 7, 8 and 9 are notes. For item 2, advise-3 argued that "attached" already implies the reconnect paths survive, and that an implementer who unlinks them fails the first reattach test. I accept that, so it stays non-blocking.

Two items survive the steelman. They are the same class advise-3 held as blocking: read literally, the contract either stops a healthy guest or never resumes a dead one by its own rules.

## C1. The slice is host-global, so a second BEAM on the host stops production guests (blocking)

Today `Cleanup` reaps only what it could have created. It matches hypervisors by `socket_dir` and TAPs by `tap_prefix`. Both differ per environment: `config/test.exs` sets `socket_dir: "/tmp/mjolnir-test"` and `tap_prefix: "mjt-"`, and `config/dev.exs` sets `/tmp/mjolnir-dev` and `@vms-dev`. That scoping exists because of a real incident. The `clean_orphan_taps` comment records mjolnir-0ut: a `MIX_ENV=test` BEAM on the same host deleted production TAPs. Integration tests run on the production host (`mix test --include integration` needs KVM and root on the server).

The contract drops that scoping. The names `mjolnir-vms.slice` and `mjolnir-<id>.scope` are fixed literals. The watcher is a single host unit watching that slice. The scenario "A true orphan is stopped" says: the StateStore was readable, a scope in `mjolnir-vms.slice` has no record, so that scope is stopped.

Here is what happens. Someone runs `mix test --include integration` on 45.76.77.97. The test BEAM starts and its StateStore at `/tmp/mjolnir-test/state` is readable. It lists `mjolnir-vms.slice`, finds every production scope, finds no record for any of them in its own store, and stops them all. That is a fleet outage caused by running the tests. A dev BEAM does the same thing. The reverse also holds: a production restart stops every scope that a test run left in the slice.

**Owed:** one sentence in the spec and the ADR, plus a scenario. The slice name and the scope prefix are per instance, derived from config the same way `tap_prefix` is. A BEAM subscribes to, classifies, and stops only scopes under its own slice. The scenario: a second BEAM with a different instance namespace starts on the host and does not stop a scope in another instance's slice. The production literal can stay `mjolnir-vms.slice` / `mjolnir-<id>.scope`.

## C2. A `failed` scope is neither "inactive" nor "not loaded", and it holds the name (blocking, one line)

The death rules say "inactive or not loaded" (Liveness) and "gone or inactive" (missing unit). systemd has a third dead state, ActiveState `failed`. A scope ends in it when its result is not success. The realistic case here is the kernel OOM killer taking cloud-hypervisor on a crowded host (Result `oom-kill`), or a stop that times out into SIGKILL. A failed unit is not garbage-collected under the default `CollectMode=inactive`. It stays loaded until `reset-failed`.

Read literally, `failed` matches no death row. It falls to the ADR's "Anything else: backoff … then `:failed`". If an implementer counts `failed` as inactive anyway, the cold resume calls `systemd-run --unit mjolnir-<id>`. systemd rejects it because a unit with that name is already loaded. That refusal is not "already active", so the B1 exemption does not apply and the failure counts. Ten Monitor ticks later the guest is retired, even though its `restart_policy` was `:always`. OOM is the crash that Reconcile exists to recover from, and it is the one path the normal `mj kill`/SIGKILL tests do not exercise.

**Owed** (one line plus one scenario row): systemd `failed` is a death, like inactive. Before a cold resume, the BEAM clears a loaded, non-active unit of that name, for example with `reset-failed` or `CollectMode=inactive-or-failed` at spawn, so the restart is not refused. The scenario: an OOM-killed scope is `failed` with intent `:running` and policy not `:never`. Reconcile cold-resumes it, and `resume_failures` does not grow from a name collision.

## Non-blocking

- **N1** (carried from advise-3 N5, for `mjolnir-uepi.4`): name the paths `clean_stale_sockets/1` must keep. Those are the CH API socket, the vsock UDS, and the virtiofsd sockets of any scope classified as attach or not yet classified. One sentence in the restarter requirement would turn a test failure into a contract.
- **N2:** systemd does not report an exit code for scope units. There is no `ExecMainStatus`, only `Result`. Once the BEAM is gone, PID 1 reaps the VMM and keeps no status. "Records … exit status" can therefore only mean "Result, or unknown". Every death already routes to Reconcile no matter the status, so no decision changes. Say "exit status or systemd Result where available" so `mjolnir-uepi.3` does not chase a field that does not exist. The `{:hypervisor_exit, status}` reason today comes from the port, and only the BEAM-up spawn will still have that.
- **N3:** if virtiofsd dies while cloud-hypervisor lives, the scope stays active and the guest is attached with a dead root filesystem. That is no worse than today (`vm.ex` logs it and continues). Health probes own it. No row needed.

## Not asked for

I'm not asking for a namespace scheme, a config key name, a watcher transport, a record format, or a convergence redesign. C1 is one sentence plus a scenario. C2 is one line plus a scenario.

## What accept would name

Once C1 and C2 land, I would accept this contract: `guest-lifetime` plus ADR 0014 as revised. Each guest gets one scope in a per-instance slice. A watcher only witnesses. systemd's current state decides liveness, with `failed` counted as dead and the name reclaimed. The BEAM is the only restarter. Any active scope gets attached, no matter who finds it. Any unit that is gone, inactive or failed gets a cold resume through Reconcile's plan.
