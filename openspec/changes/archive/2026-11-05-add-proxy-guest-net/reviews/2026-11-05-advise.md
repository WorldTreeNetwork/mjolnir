## Blind pass

Written to [2026-11-05-independent-take.md](2026-11-05-independent-take.md) before opening design.md, tasks.md, steer.md, or docs/spikes. Inputs were proposal Why, the proposed requirements, and cited code; no living proxy-guest-net spec exists.

1. Pin proxy-class identity independently of a caller remembering enable_iroh=false; ordinary guests must retain their current defaults.
2. Pin the class across boot, resume, restore, and health repair so no lifecycle path silently chooses ordinary networking.
3. Require the proxy setup script to establish only the host /32 route and remove stale default routes and public resolvers idempotently.
4. Refuse a proof based only on absent IPv4 default routing: the process boundary must deny other reachable addresses, including IPv6 and other guests.
5. Pin enable_iroh=false before the guest's one-shot startup decision; preserve presets::N0 for ordinary guests.
6. Require class-aware L2 health that recognizes intentional isolation and cannot heal it into public connectivity.
7. Refuse the unmodified stock unit as success: prove actual proxy startup, usable journal storage, and permitted host-API connectivity together.
8. Pin when confinement becomes effective and make failure to install it fail closed before the proxy serves traffic.
9. Require positive loopback/host probes and negative public/alternate-address probes under the actual proxy confinement, repeated after repair and resume.
10. Tradeoff: a dedicated image/unit can minimize ordinary-guest changes, but its policy and lifecycle persistence need stronger evidence than spawn-time flags alone.

## Comparison and steelman

The strongest case against my initial concerns is the existing separation of mechanisms. ConfigureNetwork executes the guest's script (`native/mjolnir_guest_agent/src/vsock.rs:824`); the host does not inject a hard-coded default route during L2 repair (`lib/mjolnir/vm.ex:1794`). The proxy spike removes defaults and replaces the host /32 route before reporting success. The guest agent takes the false Iroh branch without starting the N0 endpoint (`main.rs:94`). Existing StateStore persistence already writes enable_iroh and base_image, and resume reads them (`vm.ex:3892`, `vm.ex:1204`). A new persistence subsystem is unnecessary.

The data-dir experiment is particularly useful: unrestricted root could reach the public address while a probe in the service cgroup could not. That distinguishes process confinement from missing routing. The real proxy remained active, with its journal directory and loopback listener. The class experiment then combined the drop-in, restricted route, and disabled agent endpoint and reports that L2 repair preserved them. The stock-unit no-go remains correctly separate. I also read the external stock service read-only: it retains DynamicUser, empty capability sets, IPAddressDeny=any, and localhost allowance; the drop-in adds only the host /32 allowance and repairs the paths.

These results answer blind concerns 3, 5, and 7 and substantially answer 4 and 8 on the tested guest. They justify keeping the selected architecture. They do not define the host's class discriminator or the behavior of the health probe that has yet to land.

## Owed before acceptance

**R1 — Define how the class is selected and retained.** Design line 28 describes an image script plus a spawn flag; line 30 promises a class-aware probe without saying how it recognizes the class. `enable_iroh=false` is already an independent ordinary-VM option (`router.ex:292`, `vm.ex:1359`), so it cannot alone mean restricted networking. Specify the authoritative class signal or image identity, its consistency with the installed recipe, and behavior for missing/conflicting Iroh options. State which resume/restore paths are supported and how they preserve that identity and false flag. A dedicated image identity is a viable answer; a new general-purpose network policy API is not required. Add a regression case for an ordinary guest with Iroh explicitly disabled.

**R2 — Define healthy isolation and repairable drift.** “Teach that probe about this class” leaves the central instrument unspecified. The current probe marks no default route dead, while `Health.do_heal/3` skips any check returning `:ok` (`lib/mjolnir/health.ex:129`). An unconditional proxy-class success would silence the warning but also stop L2 repair when its host route disappears. Specify success, failure, and repair behavior for the intentional no-default state, missing host /32 route, unexpected default/public resolver, and host reachability failure. Name the bounded reachability target and distinguish unavailable measurement from success. Add scenarios that force an actual L2 repair and verify the pin afterward. The current spec line 7 only says healing an ordinary guest must not change a proxy guest; it needs an explicit proxy-heal invariant too.

**R3 — Make the instrument acceptance reproducible.** The guest-class reproducer (`docs/spikes/proxy-guest-class/repro-command.sh:49`) prints routes, resolver, and active status, then deletes the guest. It performs no connect probes, L2 heal, relay inspection, or ordinary-guest runtime comparison. The data-dir reproducer prints failures without asserting expected results and exits zero when joining the service cgroup fails (line 44). Preserve the reported spike findings, but add an executable acceptance procedure with assertions and captured evidence for the combined class, an actually executed L2 repair, supported resume, and an ordinary control. Retain a routable unrestricted control for negative confinement probes; otherwise a public-connect failure can prove only missing routing. Cover other reachable remote addresses and IPv6, or document the verified address-family restriction. Failure to join confinement or inspect the guest must fail verification. This can be a bounded local acceptance check, with no production boot or service restart.
