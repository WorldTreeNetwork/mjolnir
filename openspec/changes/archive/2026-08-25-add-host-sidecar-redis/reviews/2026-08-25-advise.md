## Verdict

The sidecar shape is the right one: systemd not OTP, overlay bind
not loopback, AUTH not `vm.json`, not a hotel, AOF `everysec`
named. Do not `act` yet. Decision 7 as written is not implementable
without guessing a backup that can restore, and one of those guesses
(live copy of Redis 7 `appendonlydir`, or restore RDB-only while
`appendonly yes`) yields an empty dataset.

Keep: systemd; `10.200.0.1:6379`; INPUT not FORWARD; fail closed;
one password; `databases 1`; rename the guns keep `BGREWRITEAOF`;
secrets merge; no extra just verb; no `vm.json`; Hypersigil wiring
out of repo; ADR 0007 numbering.

Do not keep as written: `BGREWRITEAOF` then `rclone` of a live data
dir as the off-host object.

## Steelman against (keep systemd Redis as written)

Medusa sessions die on `mj deploy` if they live on the guest rootfs,
and they die on `just deploy` if Redis is an OTP Port next to
Postgres (`Mjolnir.Postgres.Supervisor` is `:rest_for_one`; the
Port is the BEAM’s child). The blob door already proved the overlay
path: dummy `10.200.0.1/32` (`scripts/bootstrap-host-ubuntu.sh:1000–1011`,
`lib/mjolnir/network.ex:206–209`), INPUT not FORWARD (LEARNINGS
2026-08-19), ride `deploy.sh`, never `0.0.0.0`. A second systemd
unit on `:6379` is that pattern, not a new architecture. Unprovisioned
guests still lack `REDIS_URL`. `Tenants.write_secret/4` already
merges (`lib/mjolnir/postgres/tenants.ex:274`) — Redis can `Map.put`
the same JSON. Not a hotel is correct: ADR 0005 is Postgres
`CREATE DATABASE`; Redis `SELECT` is not that.

That argument holds. It does not license a torn AOF as “backup”.

## One real tradeoff

**Sessions share fate with one host `redis-server`, not with the
BEAM, and not with a guest rootfs.**

Isolation is bind + password + renamed commands. A full disk or a
bad `redis.conf` takes Hypersigil logins down without taking Sites.
The gain is cutover-safe app VMs. The cost is a second durable
daemon whose disaster-recovery object must actually reload. Hotel
isolation is deferred.

## Findings (block accept)

1. **Live copy of the data dir is not a restore-safe object.**
   Decision 7 (`design.md` Decision 7) and the backup task say:
   unix-socket `BGREWRITEAOF`, wait, `rclone copy`
   `/var/lib/mjolnir/redis/` to B2. Redis 7 AOF is
   `appendonlydir` (base + incremental). Copying that directory
   while Redis is appending is a torn incr file. The Postgres
   analog is online and consistent (`scripts/backup-pg-tenants-b2.sh:68`
   `pg_dump`). Redis’s online consistent analog is `redis-cli --rdb`,
   **but** with `appendonly yes` Redis loads AOF on start and does
   not fall back to `dump.rdb` if an AOF dir exists or is empty.
   `CONFIG` is renamed empty in Decision 4, so restore cannot
   `CONFIG SET appendonly no`. The only method that does not
   require guessing Redis load order is a **quiesced whole-dir
   snapshot**: stop the unit (SIGTERM; AOF already `everysec`),
   copy the dir, start. Named downtime: seconds. Medusa reconnects.
   Restore is the same dir from the same snapshot — AOF + RDB
   together. Do not restore RDB-only onto a conf with
   `appendonly yes`.

   The exit path `redis-cli --rdb` over `REDIS_URL` stays. That is
   Duke leaving with the keys, not the host timer object.

## What is solid

- Bind `10.200.0.1` only, dummy already assigned, `allocate_ip/1`
  already skips it (`lib/mjolnir/network.ex:157–176`).
- INPUT trap named; ubuntu helper shape exists for 5432/7222
  (`scripts/bootstrap-host-ubuntu.sh:1014–1042`).
- `install-blob-door.sh:27–30` fail-closed dummy check is the
  template; Redis must copy that, not Debian `bind 127.0.0.1`.
- Secrets path is the path deploy actually reads
  (`lib/mjolnir/deploy/orchestrator.ex:405–413`).
- No `just deploy-redis`. Hash-compare restart is load-bearing:
  `install-blob-door.sh:131` **always** restarts the door — Redis
  must not copy that line.
- `buzz-local-client` “Host sidecar is control-plane only” correctly
  not MODIFIED (that SHALL is the OTP Postgres process).
- ADR 0007, not 0006.

## Implementer gaps (not send-back)

- `chown redis:redis` on `/var/lib/mjolnir/redis`;
  `ReadWritePaths=` under `ProtectSystem=strict`.
- URI-encode the password in `REDIS_URL` the way
  `Tenants.database_url/3` does (`tenants.ex:253–254`).
- Grow `allow_*_input` in `bootstrap-host-ubuntu.sh`; live host is
  Ubuntu. Arch bootstrap has no dummy/5432/7222 helpers today
  (`scripts/bootstrap-host-arch.sh`) — do not discover Redis on Arch
  as the v1 path.
- `ExecStartPre` dummy check so `Restart=on-failure` does not loop
  without falling back to `0.0.0.0` (Redis will not bind `*`; it
  will fail — still do not busy-loop).
- Disable stock `redis-server.service` so we do not inherit
  `bind 127.0.0.1`.
