## Verdict

The four previous blockers are **answered in the spec**. Act is still
blocked because the accepted *design.md* contradicts that spec on two
load-bearing sentences. Implementers are told `design.md` is the full
argument.

| Prior blocker | Status |
|---|---|
| Wake producer unnamed | Closed. Ingress is the producer (Decision 10, spec). |
| HTTP-only; queue-before-admit | Closed in spec. All untrusted ingress; admit before `pending_messages`. Code still queues first (`lib/mjolnir/vm.ex:794-801`) — that is later `act`. |
| Dormant / `:stopped` / `:never`; facade-only thaw | Closed. `:never` finalize via Reconcile (`lib/mjolnir/reconcile.ex:169`); `signal_done` refused like `secrets_mode: :persistent` (`lib/mjolnir/vm.ex:1118-1124`). Other topologies named. |
| Protocol crate owns all admission | Closed in spec + ADR one-screen. **Open in design.md Decision 4.** |

## Steelman against

Every current `deliver_message/3` caller is in one BEAM. A signed
attestation scheme is ceremony if a process allowlist would hold I5
today. The spec is buying the *vocabulary* for a second trust domain
(gateway, CDN) that is not built yet. Counter: `/messages` is already
an external door; the verdict list must exist before
`nod-identikey-admit`. A v1 evaluator may be that allowlist.

## Tradeoff

Fail-closed before `pending_messages` turns evaluator outage into a
silent drop. Today, queue-then-restore is durable for any sender
(`dormant_registry` persist). Buzz can re-read the relay; non-Buzz
VM-to-VM senders lose a guarantee. Right for I5. Say so when
implementing.

## Findings

1. **Blocker (docs).** Decision 4 still titles the facade as
   identikey-protocol (`design.md:67-82`). Spec `89-99` and ADR
   `14-17` say protocol = wire + validators; host = lifecycle +
   evaluator. Rewrite Decision 4.
2. **Blocker (docs).** Decision 5 still grows “named databases”
   (`design.md:84-94`). Spec `123-130` and ADR say schemas in one
   catalog DB. Rewrite Decision 5.
3. **Should-fix.** “Lifecycle generation” is not StateStore’s
   write generation (`state_store.ex` bumps on every persist). Name
   a boot/epoch field or say “not the persist generation.”
4. **Nit.** Default verdict for authenticated `mj message` on a
   non-Buzz dormant VM is unstated.
5. **Nit.** Guest-originated vsock wake: which proxy attests? Defer
   to `nod-mailbox-control` in the spec text.

## What is solid

Spec nouns are code nouns (`pending_messages`, `queue_message/3`,
`restart_policy: never`, `revive_authorized?`). Running mentions stay
on Nostr. Dormant wakes go ingress → attest → deliver. Guests stay
off Distributed Erlang. Sidecar is a catalog. `:never` already
finalizes in Reconcile. License split is concrete.

## Implementer gaps (after the two design.md lines)

- Attestation transport on `deliver_message/3` (today: vm, from, payload).
- Actor/event → VM routing for dormant Nostr ingress.
- Replay/TTL inside one lifecycle epoch (`nod-identikey-admit`).
- Precedence when `:never` and `secrets_mode: :persistent` both apply.
