## Blind take (written before design.md / tasks.md)

1. **Pin:** catalog = closed list + recipe in repo; undeclared =
   unmanaged, never auto-deleted. Only way `@base/tatastu-agent`
   becomes a known state instead of a surprise.
2. **Pin:** "Toolchains are not OS roots" with its reject clause.
   `build-deploy-base.sh:225-226` bakes `node@20` + `bun@latest`
   via `mise_use`; the ubuntu recipe installs only the `mise` binary
   (`build-rootfs-ubuntu-24.04.sh:187`). The whole delta between
   them is one cached layer. Retire is right.
3. **Pin:** inject is a refresh, not a crutch. `vm.ex:2227-2242`
   already has no `else` and `rescue`s to `:ok`; `guest-agent.sh:130-155`
   already verifies binary + unit + wants symlink and exits 1. For
   ubuntu / CI / buzz the spec describes shipped code.
4. **Refuse:** `arch` as a declared v1 name *under* the
   "boots without inject" SHALL. `build-rootfs-arch.sh:19` sources
   only `terminfo.sh`; `:163-190` hand-writes the unit inside
   `if [[ -n "$AGENT_BIN" ]]`, else prints `WARNING` and continues;
   `:15` defaults `AGENT_BIN` to empty; there is no
   `verify_guest_agent` and no `ALLOW_NO_AGENT` gate. The recipe
   cannot fail the way the SHALL says every declared recipe SHALL.
5. **Refuse:** importing "Pins are immutable; aliases move" as
   living SHALLs at fold. D6 is explicitly unbuilt (`mjolnir-b0gb.6`).
   It belongs in the ADR as an accepted decision and in a PENDING
   delta, not in `openspec/specs/base-images/`.
6. **Refuse (same rule):** the "Deploy default" scenario.
   `orchestrator.ex:50` is still `"deploy-node-bun"`, used at `:113`
   and named in the moduledoc at `:18`. The SHALL is false until
   `remove-deploy-node-bun` lands.
7. **Contradiction:** "declared when … appears in the catalog v1
   list" (spec.md:3-9) vs "Pins SHALL live under `@base/`"
   (spec.md:144-145). A pin `ubuntu-24.04-20260827` is not in the
   list, so the undeclared rule (spec.md:16-18) reports every pin
   as unmanaged next to `tatastu-agent`, and later pin GC would be
   auto-deleting "unmanaged" names.
8. **Tradeoff accepted, hole named:** v0 in-place rebuild on the
   alias. "Running `@vms/<uuid>` clones SHALL NOT be destroyed"
   (spec.md:114) is a BTRFS property, fine. What *does* break is the
   deploy cache: `cache_key.ex:74-75` hashes `parent_layer_id` as a
   string, `builder.ex:102` defaults that to the base-image name,
   `orchestrator.ex:122` passes the name. After a v0 rebuild every
   existing `deploy-*` layer parented on the alias is a silent hit
   on a different filesystem. D5's operator sequence must say so.
9. **Watch:** `mjolnir.toml` has no `base_image` key
   (`manifest.ex:122` reads `runtime`; `port`, `steps` elsewhere).
   The "Deploy default" GIVEN references one. Forward-looking is
   fine; the delta must not SHALL it.
10. **Tradeoff:** D4's independent debootstraps mean four preambles
    drift independently; the shared-helper contract covers only
    agent / mise / terminfo. Accept for v1 — a DSL is the wrong
    fix — but the ADR should name what sharing does *not* cover
    (apt list, sysctl, the network hook), since the hook is
    boot-critical and is exactly where copy-paste rot bites next.

## Findings (send-back grade)

1. **`arch` recipe cannot satisfy "Catalog image boots without
   inject."** spec.md:78-84 / ADR 0009 line 21-24 / design.md D3.
   `build-rootfs-arch.sh:15` (`AGENT_BIN` default empty), `:19`
   (only `terminfo.sh` sourced), `:163-190` (hand-rolled unit
   inside `if`, `WARNING` fallthrough, no verify, no
   `ALLOW_NO_AGENT`). Either (a) the arch recipe sources
   `scripts/lib/guest-agent.sh` and calls `install_guest_agent` +
   `verify_guest_agent` like the other three (five lines; the
   helper is distro-agnostic — it writes a unit and a symlink), or
   (b) the delta scopes the SHALL to the three ubuntu recipes and
   ADR D2 marks `arch` "declared, D3-exempt until its recipe adopts
   the helper." (a) is better and is within this change's D5
   operator landing; (b) is honest. Either way the fold must not
   import a SHALL that a declared member's recipe violates.

2. **D2 and D6 define "declared" incompatibly.** spec.md:3-9 vs
   spec.md:144-145; ADR lines 2 and 6. Add one sentence to the
   catalog requirement and ADR line 2: *a pin produced by a
   declared alias's recipe is declared (archived), not unmanaged;
   unmanaged is a name with no recipe in this repo.* Without it,
   `add-base-image-list` will freeze pins as strays and D6's "GC of
   unreferenced pins is later" contradicts "never auto-deleted."
   Flagged 2026-08-28, still open.

3. **Fold split is unenumerated.** tasks.md:25-28. Replace the
   prose gate with a per-requirement / per-scenario table: fold-now
   vs PENDING and which node (`remove-deploy-node-bun`,
   `add-base-image-list`, `add-base-image-pins`) each PENDING item
   waits on. The folder should not be the one deciding which SHALLs
   are "already true of the design" — that is how 2026-08-16
   happened.

4. **D5 v0 operator sequence omits deploy-cache invalidation.**
   design.md:182-190 and ADR line 5 (26-32). Add a step: *after an
   in-place alias rebuild, delete (or the operator SHALL delete)
   `@snapshots/deploy-*` layers whose parent is that alias.*
   Mechanism: `cache_key.ex:74-75` + `builder.ex:102` +
   `orchestrator.ex:122` — the parent is the alias *string*, so a
   changed filesystem under the same name is a cache hit. Latent
   until retire flips the default; live from then until b0gb.6.
   This is D6's own argument applied to the v0 it grandfathers.

## Findings (non-blocking, for the implementing nodes)

- **Retire (`mjolnir-b0gb.2`):** the moduledoc at `orchestrator.ex:18`
  claims `deploy-node-bun` "does not mount that share automatically";
  re-verify against `ubuntu-24.04` before flipping. The 2026-08-28
  review's StateStore sweep for recorded `base_image: "deploy-node-bun"`
  before subvolume deletion still applies.
- **Health (`mjolnir-b0gb.4`):** the noisy-inject fix is an `else`
  on `vm.ex:2230` with a `Logger.warning`. Note the `rescue` at
  `:2239-2241` also swallows a failed copy into `:ok`; a corrupt or
  unreadable agent binary is currently indistinguishable from a
  missing one. Warn on both.
- **`vm.ex:189`** documents the spawn default as `"ubuntu-24.04"`;
  the real default is `Application.get_env(:mjolnir,
  :default_base_image)` at `vm.ex:1906`, overridable by
  `MJOLNIR_BASE_IMAGE` (`runtime.exs:69-71`). The spec's "Spawn
  default" scenario is true only when that env is unset; say so or
  drop the env from the scenario's GIVEN.
- **D4 sharing contract:** name in ADR line 4 what the helpers do
  *not* cover (network hook, apt list, sysctl) so the next recipe
  author knows where drift is permitted and where it is a bug.
