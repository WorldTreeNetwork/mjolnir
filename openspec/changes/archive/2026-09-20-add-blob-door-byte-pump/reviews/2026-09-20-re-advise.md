## Independent take — written before opening design, tasks, delta, or prior review

1. Pin B2 confirmation as the sole acceptance boundary; a local rename cannot prove durability.
2. Pin incremental hashing and bounded streaming for large bodies, including limit enforcement without Content-Length.
3. Refuse request-controlled filesystem paths: validate every object identifier before cache access, including GET, HEAD, and `.obao`.
4. Pin actual retained object bytes to the cache budget under concurrent PUT promotions and GET fills; an atomic counter alone is insufficient.
5. Refuse a cache lookup/open race turning a B2-present object into a 404; cache disappearance must fall back to origin.
6. Refuse publication of incomplete GET fills, including failures during final flush or sync and client cancellation.
7. Pin cache-root exclusion using resolved paths at installation and process startup, including symlinks, parent segments, and fallback paths.
8. Preserve the existing hash layout, repeat-PUT semantics, overlay surface, and credential boundary from the living spec.
9. Tradeoff: staging on disk bounds RAM and enables retryable file upload, but consumes temporary disk beyond the retained-cache budget.
10. Require focused adversarial scenarios for these boundaries; contract acceptance must leave implementation and operational proof visibly owed.

## Steelman against the independent take

The strongest argument for accepting now is that a disposable cache can
fail admission without weakening B2 durability: after canonical confirmation,
an accepted PUT need not remain locally cached, and an unsuccessful GET fill
can be discarded while origin bytes are streamed. The amended contract
makes those boundaries explicit. It also leaves act free to choose how to
coordinate admission and eviction; prescribing a particular lock or a new
storage abstraction would add no necessary contract protection.

The retained-byte budget is an `objects/` bound, not a promise that temporary
incoming files or open-but-unlinked files consume no disk. Disk staging and
finite free space remain the acknowledged tradeoff. The living spec's B2
confirmation, content-addressed layout, repeat-PUT behavior, overlay, and
credential boundaries continue to apply. No competing architecture is needed.

Requiring the Rust repairs before accepting this amendment would conflate
contract review with act verification. Conversely, acceptance does not
establish that the current binary meets these requirements. The four
unchecked repair tasks accurately preserve that distinction.
