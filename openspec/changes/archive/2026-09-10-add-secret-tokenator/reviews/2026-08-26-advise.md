## Verdict

Vault + `api_url` + holder-plus-bearer is the right host shape.
Do not treat this architecture as ready to `act` until (1) the
Auth plug branch is named so redeem cannot land on
`@skip_auth_paths`, (2) the protocol send-back on holder/hop is
amended, (3) nonce single-use and holder-key encoding are in the
deltas. Banner stays `ACTIVE BUILD`.

## Steelman against

**New sidecar port, like blob door.** Strongest version: biscuit
verify is Rust; Elixir restart is expensive (Cleanup kills VMs);
blob door already proved “don’t put this in the BEAM.” Why the
design still holds: the vault is SecretStore, in-process, 0600
files the BEAM owns (`put_opaque/4` at
`lib/mjolnir/secret_store.ex:155-168`; path
`_opaque/<kind>/<id>/<key>` at `:498-499`). A second binary
opening those files is a new trust boundary for the PAT. Blob
door does not read OTP state. Tokenator does. Restarting Elixir
for the first biscuit NIF is accepted in Decision 2. Keep the
port off the overlay.

## One real tradeoff

Return PAT bytes to Z vs a GitHub proxy that never copies the
PAT into the guest. Bytes are the smaller v1. They also mean Z’s
virtio-fs snapshot can grow a copy of the PAT if anyone writes
it down. Decision 4 names the proxy as later. Add the guest
constraint: redeem into process memory / tmpfs; do not write
the value into the virtio-fs rootfs. That is a one-paragraph
design amend, not a new node.

## Findings (send-back)

### 1. Auth plug has no biscuit branch. `skip_auth` is the trap.

`lib/mjolnir/api/auth.ex:34-68`: skip list is `/api/health` and
`/auth/*`; then sites token, localhost bypass, JWT. Guests on
`10.200.0.1:4000` do **not** get localhost bypass (peer is the
dummy, not loopback — `localhost_bypass?/1` at `:139`). Good.

Decision 2 says redeem needs no JWT. If act puts
`/api/secrets/redeem` and `/challenge` on `@skip_auth_paths`,
those routes are fully unauthenticated and only *application*
code can fail-closed. Sites tokens exist specifically so a
narrow credential is not upgraded (`auth.ex:20-24`). Redeem
needs the same shape: a **fourth `call/2` branch** that accepts
Biscuit+holder, confers *only* redeem (and challenge), and
cannot spawn VMs. Name that branch in Decision 2/3. Do not use
skip_auth.

### 2. Blocked on protocol send-back.

Holder-key encoding, hop vs nextKey, and whether *every* Biscuit
is holder-bound live in `update-identikey-capability`
`reviews/2026-08-26-advise.md` findings 1–3. This ADR injects
`holder(<pk>)` (design.md:89-90) without a canonical `pk`
string. Amend the protocol first or duplicate the encoding here.

### 3. Challenge nonce is not in the spec.

auth-challenge v1 persists used nonces until `exp`. Design
step 1 issues `{nonce, aud, exp}` but
`specs/secret-tokenator/spec.md` “Holder proof fail-closed”
does not require single-use. Replay of a captured redeem POST
would work until `exp` if the nonce is not burned. Add a
scenario: reused nonce fails, no secret.

### 4. Opaque layout matches code; namespace collision is unnamed.

`get_opaque("secrets", "github-pat-ci", "value")` is
`_opaque/secrets/github-pat-ci/value` (`:498-499`). Buzz nsec
is `_opaque/vms/<id>/` (LEARNINGS 2026-08-17 / mjolnir-1pe).
`kind="secrets"` does not collide. `validate_opaque_segment/1`
rejects `/` and `..` (`:502-508`). Secret ids must be
path-safe; say so on mint. `put_opaque` is documented as
“VM-scoped material” (`:151`) — secrets are **not** VM-scoped;
amend that comment in the runtime node, not here, but the
architecture should say the vault is host-global, not per-VM.

## What is solid

- Opaque vault over env files and mailbox payloads.
- No `tokenator_url`, no extra overlay port. `api_url` already
  exists.
- Bearer-only rejected.
- Logging metadata not `value`.
- Recrypt-data-is-not-this-vault scenario.
- Split of NIF / redeem / mint / hop into later landings, and
  the 2026-08-16 warning not to fold unimplemented HTTP SHALLs.

## Claims verified against code

- `put_opaque/4` / `get_opaque/3` exist; 0600; no envelope
  (`secret_store.ex:149-185`).
- Opaque path is `_opaque/kind/id/key` (`:498-499`).
- Guest `:4000` is not loopback bypass (`auth.ex:11-12, 56-59,
  139+`).
- `@skip_auth_paths` is only `/api/health` (`:34, 66-68`).
- Envelope SecretStore is a different API (`put/3` at `:52`)
  and cannot hold an unsigned PAT (LEARNINGS mjolnir-1pe).

Do not implement from this review. Amend, then Fable advise.
