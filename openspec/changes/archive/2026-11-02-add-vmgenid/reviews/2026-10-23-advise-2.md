## Blind take

Written before opening the delta, design, tasks, or previous review; based only on the permitted proposal, living spec, and code.

1. Pin the snapshot's captured kernel capability; replacing a host kernel file cannot upgrade saved RAM.
2. Preserve legacy thaw under the existing reseed gate without claiming VMGenID protection for an unrecorded capture.
3. Require a recorded capable capture to demonstrate a guest-visible generation-id change before reachability, with failure preserving the image.
4. Refuse post-reseed random-output divergence as proof of VMGenID: the existing host entropy injection can cause it independently.
5. Keep reseed and wall-clock ordering explicit; neither a changed generation id nor a vsock pong alone satisfies today's publish gate.
6. Refuse a claim that the kernel mechanism resets arbitrary userspace PRNG state or proves all restored userspace ran after notification.
7. Preserve original-id thaw when parked; a live-source fork must own separate host resources and a clone of the pinned rootfs.
8. Copied IP, MAC, and Iroh key require an explicit restricted reachability contract that cannot advertise the fork as the original endpoint.
9. Failed fork cleanup must preserve the running source, its publication, and the reusable snapshot; copied networking must not disrupt that source.
10. Accept vsock-only fork utility as a tradeoff for deferring guest identity regeneration, provided its health and ticket semantics reconcile with the living Iroh requirement.

## Comparison and steelman

The amended delta answers the three questions from `2026-10-23-advise.md`. The independent take identifies obligations, not a requirement to replace this design.

1. **Captured kernel and legacy images:** the added requirement records the captured kernel's `CONFIG_VMGENID` capability and explicitly says a replacement host kernel cannot change that record. An absent or negative record retains thaw under `Entropy.reseed`, retains the image, and makes no generation-id claim. The proposal requires cold-booting the candidate kernel before the disposable freeze/thaw proof. This resolves the legacy compatibility ambiguity without discarding old snapshots.
2. **Evidence independent of reseed:** a recorded capable capture requires a guest-observed id different from capture, and the two-guest scenario requires different observed ids. Missing observation prevents publication; post-`Entropy.reseed` urandom samples are explicitly inadmissible evidence. The design acknowledges the notify race, and the delta disclaims resetting userspace PRNGs. The accepted claim is observed generation change with the retained reachability gate, not proven pre-userspace ordering or generic application RNG reset. The actual observation mechanism and disposable result remain implementation/proof work; their absence today does not require a new design.
3. **Second-guest reachability:** the modified requirement explicitly substitutes vsock-only access for a second public endpoint. It requires a distinct VM id, CID, virtiofsd socket, and TAP, backed by a clone of the pinned rootfs, while forbidding a ticket and gateway publication for the copied identities. This fits the existing remapping boundary instead of treating a ready response with the copied Iroh key as independent addressability. The first guest must remain running and published, including on fork failure. That obligation also rules out a fork implementation whose copied networking disrupts the first guest.

The tradeoff in blind-take line 10 is answered by distinguishing running with restricted vsock access from healthy and publicly published. The living clock and Iroh health requirements remain binding: a vsock pong still cannot establish Iroh health, and a copied Iroh identity cannot justify a second ticket. The delta does not grant such health or publication. Existing `VM.thaw/2` and `Publish.run/1` still require implementation changes to realize this contract; accepting the proposed behavior does not certify the current code.
