## Edits required before implementation

1. **High — establish the media source at pairing.** Design:76–88, spec:73, tasks:35,42–44. The weak receiver proves which WHIP session gets a call. It proves nothing about which session supplied the media to the independently resolved WHEP subscription. At the pin, whep.rs:163 awaits source resolution. Egress builds Target.path from a resolved broadcast reference, Target.instance from the optional catalog field, and Target.track from the rendition (egress.rs:293–304). It follows cross-broadcast references when subscribing (egress.rs:307–323). Two live generations can both serve the same track name. The pinned replacement test explicitly leaves the prior session open (whip.rs:345–362).

   Require a binding between the actual served broadcast instance and the paired WHIP generation, with the resolved target path and active video track checked on rendition changes. When the catalog omits its instance, accept an equivalent trusted binding from the actual media subscription; otherwise ignore the viewer request. A table generation plus a track string alone is insufficient. Preserve a working positive case on the default wire: e.g., establish a generation-bound source during pairing or carry a verifiable instance reference for local WHIP renditions. An identity minted locally by a receiving hop alone cannot attest the WHIP route. Test address replacement **during** WHEP source resolution with both sessions alive, identical track names and an omitted catalog instance. Cover a sibling catalog reference with the same track name. Only the proven source may receive feedback; count unresolved cases and verify neither publisher receives those requests. Keep the existing stale-handle test, but distinguish replacement while S1 lives from retirement after S1 ends. If replacement itself retires S1 feedback, specify that invalidation explicitly.

   **Keep the embedder SHALL here.** It is an integration obligation this node implements in its harness and demonstrates with D3a–c. Include it in the .13 handoff for product wiring.
2. **Medium — implement the advertised default and park a held request safely.** Design:38–44,98–110 and spec:26–29. Derived Rust Default gives Duration a zero value; enabling an otherwise-default policy would remove the advertised second of spacing. Use an explicit one-second default, reject invalid zero intervals that could cause timer spin, and test enabling the policy from defaults. Record a send only after the writer actually accepted the PLI (the pinned helper returns Ok even without a writer, session.rs:479–484). No-receiver handling already preserves the session and one pending bit. Specify that an unsendable pending request disarms expired deadlines until a receive-stream transition or a strictly future retry. A first keyframe cancels it; a first eligible delta may release it. Test elapsed time with no RTP, eventual cancellation/release and unchanged disabled behavior.
3. **Medium — preserve the existing frame admission decision.** Spec:37,52 and tasks:35 (P5). “The frame SHALL still be forwarded” also covers keyless startup deltas and old frames the pinned IngestOrder drops (session.rs:296–305). Say that the loss cause can request a PLI independently and that the existing admission decision still controls forwarding. Test a usable discontinuous delta and one already ineligible for forwarding. This implements the owner's “forward usable deltas” decision.
4. **Medium — make the baseline and build gates executable.** Tasks:17,20,25–26,53–56. K1 must explicitly build the scratch **consumer** against the pristine path crate and separately run the vendor tests on both platforms. Point the scratch consumer's relay path dependency at the intended checkout. After K0/K1, capture H0/H1 against the unpatched pin before switching the harness to K4. H0 currently requires every new field to appear against the unpatched edge, including a requester result that does not exist there. Use common external observations or identified measurement-only probes for the matched baseline; mark patch-only fields unavailable and self-test them on the patched build. Use the same byte-counting boundary for all three cost runs. Report bitrate differences over equal windows and quality differences separately. If alignment fails, identify the missing quality result in the PR. Neither PSNR nor capped bitrate directly measures the earlier delta-only counterfactual. Make the adopt box explicitly depend on F, E and the latency runs named in ASK 4.

All five owner decisions in tasks:67–73 match the bead, including the cost evidence inside the PR. No further owner choice is needed for these edits.
