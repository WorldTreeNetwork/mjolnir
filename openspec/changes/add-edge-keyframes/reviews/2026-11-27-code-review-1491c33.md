## Saturation hook and isolation

`Keyframes::saturate` is an explicit public library policy field, compiled into the carried patch; it is **harness-intended, not cfg(test)-only**. Its default and trial values are false. The only enabling call site found is the harness's WHIP `KEYFRAME_POLICY=saturated` branch, which enables the gate and sets the one-second floor. WHIP with `enabled=false` never installs this policy on the session or changes track refresh, even if the unused saturation bit is set. The default and trial paths therefore retain their previous behavior.

The hook arms a Period ingest cause at the floor. Accepted sends rearm from their send time; keyframe cancellation clears held causes but preserves the armed floor deadline. This is materially different from period=1s, which restarts on keyframes. The committed helper verifies repeated floor preservation after an accepted send, and the independent session fixture delivers a keyframe at t=100ms and observes the Period attempt at t=1s. Missing/refusing writers still park; saturation does not override that rule. This is suitable instrumentation for the named continuously eligible ingest-cause F run when a working receive stream exists. It does not itself measure bitrate, encoder response, or recovery.

There is no Viewer cause, subscriber-supplied saturation flag, requester path, or new viewer-to-ingest feedback. Egress keyframe feedback remains logged/dropped.
