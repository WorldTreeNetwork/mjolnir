## Findings and smallest repairs

**P1 — F1: Admission can come from a redirected origin.** `src/room.js:113–135` (also media POST at 270 and DELETE at 202). Default fetch follows redirects, and the response URL/redirected flag is never checked. R1 redirects configured `/admit` to a second origin returning matching root/intent/no-store JSON; join succeeds and camera is requested. The token binding is reconstructed locally (`token: mint.token`), so origin provenance is the essential missing check. This does not establish a CORS bypass or cross-origin Authorization leakage: the native-fetch repro has no browser CORS enforcement and browsers strip cross-origin Authorization; a foreign response still must satisfy browser CORS where applicable. It establishes the unguarded trust transition. Same-origin redirects can also forward credentials and SDP to unintended paths. Small repair: `redirect: "error"` for all credential-bearing requests, explicit `referrerPolicy: "no-referrer"` for standalone module calls, and strict configured URL parsing (no credentials/query/fragment; HTTPS except explicit loopback development). The current origin regex accepts those malformed forms and arbitrary HTTP hosts. Keep the current no-referrer page metadata and fragment stripping.

**P1 — F2: Local release depends on unbounded network DELETE.** `src/room.js:195–211, 395–402, 410–425`. R4 leaves DELETE unresolved for 2.1 seconds: teardown has not completed, camera track is unstopped, and PC remains open even though status no longer exposes an incumbent. The accepted proposal specifies a two-second bound. Expiry uses the same path. Successful replacement waits for old DELETE before closing old tracks or arming the new expiry timer; one hung request therefore also leaves the new generation without its deadline. Small repair: synchronously invalidate owned operations, bound/abort cleanup requests, guarantee local release in finally, and arm successor expiry immediately at commit. Explicit leave must invalidate both generations before awaiting either one's network work. Report cleanup failure rather than unconditional success.

**P1 — F3: Candidate cleanup is incomplete on asynchronous failures and supersession.** `src/room.js:254–282, 295–302, 348–351, 384–389`. R5 makes createOffer reject: join rejects rather than returning setup_failed, leaving the camera, PC and candidate live. setLocalDescription and response.text rejection have the same missing outer cleanup. R6 returns a valid Location with bad SDP: setRemoteDescription fails before the Location is recorded, so no DELETE is attempted for the allocated session. R7 supersedes a candidate with an unresolved offer: only its tracks stop; its PC stays open until that old operation resolves (potentially forever). ICE gathering/readiness timers are also outside generation-owned timers. Small repair: one exception-safe candidate lifecycle, immediate generation abort/release on supersession, own every timer/listener, record a validated returned session before parsing/applying its answer, and clean late responses without affecting the incumbent. Shared track ownership/refcounts promised by D2 are absent (`release` blindly stops tracks); cover reuse or enforce independently cloned ownership.

**P1 — F4: Peer recovery fans out and leaks transports.** `src/room.js:279–280, 309–333`. R8 emits disconnected then failed on a playing peer: two retry timers cause two new WHEP requests; the original PC remains open and four PCs are retained including the publisher. Repeated events from old PCs can continue scheduling. R9 makes WHEP fetch throw: every retry retains another open PC because this return bypasses `fail`. Failed/timeout peer sessions accumulate until generation teardown. Small repair: one current attempt/PC and one timer per path, deduplicate failure signals, retire and DELETE the old attempt, close on every failure branch, and apply bounded exponential backoff consistently. Preserve terminal 403/codec behavior and incumbent retry ownership during candidate work.

**P2 — F5: Freshness, immutable inputs and commit conditions are not enforced at each boundary.** `src/room.js:231–267, 289–305, 340–384`. R2 crosses expiry between admission validation and camera access: camera still opens. R15 crosses expiry while createOffer awaits: a media POST still occurs after expiry. R3 mutates the caller's peer array during preflight: the publisher commits, then join throws reading an absent admission for the changed path. No inputs are snapshotted. R11 returns WHIP 200 with answer/Location and join commits, despite the explicit 201 contract. Small repair: copy/freeze validated attempt inputs, recheck ownership and freshness after every await and immediately before camera/PC/POST, require 201, and use the earliest admitted deadline. The genuine gateway currently returns the same token expiry across intents; inconsistent-expiry responses are not claimed as an observed gateway bug.

**P2 — F6: Path validation does not match the gateway's canonical grammar.** `src/room.js:42–45, 147–154`; gateway `edge.rs:1535–1555`. R10 shows local acceptance of forbidden percent escapes, incomplete percent encodings, and paths exceeding gateway depth 32. These cause requests when the contract requires pre-request rejection. Conversely the client imposes a 512-character limit rather than gateway's 4096-byte full-root bound; it does not check full-root depth/byte length. Canonical decoding and comparison must be defined once and matched on the client, including encoded traversal and single-decoding rules. This is not a demonstrated auth bypass: the actual gateway refuses these inputs.

**P1 — F7: Preview/media attachment ignores generation ownership.** `page/boot.js:51–56, 121–127`. The global getUserMedia wrapper writes local preview before the module can check ownership. A candidate immediately replaces incumbent preview; a failed candidate leaves the preview on stopped tracks, and a late candidate can overwrite a newer preview. R14 resolves camera after Leave and reattaches preview. R13 delivers two successive audio/video pairs: all four tracks remain in the same remote stream. Combining audio and video from one current subscription is correct, but retaining old subscription tracks is not; retries can retain ended video or duplicate live audio. Small repair: attach through generation/peer-attempt callbacks only after ownership checks, replace the stream when its attempt changes, remove ended/replaced tracks, and clear all views on leave/expiry. Preserve the incumbent local view when a candidate fails.

**P2 — F8: “Playing” and call status are not tied to actual playback/lifecycle.** `page/boot.js:24–25, 56, 73–106`. R12 starts with waiting, then changes module peer state and delivers a track: the tile remains waiting because paint only runs after a button action. Conversely an ICE-connected peer with rejected `video.play()` is labeled playing on repaint. Expiry and peer termination also have no UI notification; Leave clears only local video, leaving peer tiles and labels stale. No joining progress is shown, errors are raw codes, and button handlers do not catch rejected promises. Small repair: state notifications from the module plus media playing/waiting/ended/error listeners, a user-gesture playback recovery button, meaningful error/retry copy, explicit pending states, and stale-action suppression. Do not equate ICE readiness with decoded media.

## Security, licence and UI positives/limits

Configured origin is read from build configuration, never invitation/query/relay_host. Admission is fetched for publish and each named subscribe, not accepted as caller JSON. Root/kind comparison order, operation/broadcast echo checks, no-store requirement, finite freshness on arrival, bearer/root on media requests, strict relative session Location regex, and known refusal handling are present. Camera waits for the preflight loop in ordinary paths. Late camera tracks are stopped by the module, and ordinary failed replacement preserves the incumbent. RetryMs bounds and maximum seven named peers exist. The page strips the fragment and has no storage/logging of tokens.
