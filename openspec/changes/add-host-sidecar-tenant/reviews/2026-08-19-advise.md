## Verdict

Send it back. The hotel shape is the right reopen. The bind address,
the OpenSpec delta, `Tenants.ensure`, and backup as written are not
implementable without guessing — and one of those guesses (`listen_addresses
= '10.255.255.1'` on an address the tree never assigns and never
reserves) crashes the control-plane sidecar on every boot.

Keep: one OTP postgres Port; `CREATE DATABASE` per declared tenant, not
a schema in `mjolnir`; Buzz event logs stay off; overlay TCP not
virtiofs/`extra_mounts`; tenant role is not `mjolnir_sites`; unprovisioned
guests stay out; secrets at `Runtime.start` never `Builder.build`; ADR
0002 items 1–6 and 8–9 stand.

Do not keep as written: `10.255.255.1` as “the host overlay address
already used by guests”; MODIFIED requirement renamed so fold cannot
replace the living SHALL NOT; backup “off `@vms`” as the durability
story; the PENDING `add-buzz-local-runtime` collision as a non-box
handoff.

## Steelman against (keep the hotel as written)

`mj deploy` destroys the guest rootfs. A shop catalog is not a derived
index. The alternatives Duke discarded — mount a host data dir into
every cutover VM, or run a second long-lived data VM — add a filesystem
contract or a second postgres to operate. The OTP sidecar already
exists, already survives cutover, already has `initdb` / conf-write /
Port supervision. A second `CREATE DATABASE` is a policy reopen, not a
new daemon. Overlay TCP with a dedicated scram password is a smaller
hole than virtiofs of the peer-auth Unix socket (the path the old spec
named). Unprovisioned guests still have no secret. Buzz logs still
SHALL NOT land here.

That argument holds. It does not license an unbound IP, a renamed
requirement, or a dump next to the data directory.

## One real tradeoff

**Shop catalog shares fate with Sites and with the BEAM that rewrites
`postgresql.conf` on every boot.**

Isolation is `CREATE DATABASE` + bind address + password, not a
hardware VM boundary. `Mjolnir.Postgres.Server.write_conf_files/1`
overwrites `postgresql.conf` and `pg_hba.conf` every start
(`lib/mjolnir/postgres/server.ex:224–265`). A missing overlay IP, a
bad `listen_addresses`, or a `pg_hba` that is too wide takes `mjolnir`
down with Hypersigil — supervisor is `:rest_for_one`
(`lib/mjolnir/postgres/supervisor.ex:38`). Backup and a public-NIC
closed check are the mitigations the design named. They only count if
the bind address actually exists, is reserved out of the guest pool,
and the dump is off the host disk that also holds `/var/lib/mjolnir/pg`.

## Findings (block accept)

1. **`10.255.255.1` is inside the guest allocation range and is not a
   host address this tree assigns.** Guest IPs are `SHA256(vm_id)` into
   `10.200.0.0/10` = `10.192.0.0–10.255.255.255`
   (`lib/mjolnir/network.ex:144–178`,
   `docs/security/network-isolation-guide.md:36`). Last octet `.0`/`.255`
   are skipped; **`.1` is not** — `o4 == 0` is rewritten to `1`, so
   `10.255.255.1` is a legal guest IP. TAP devices have **no host IP**
   (`network.ex:19–21`, `docs/architecture.md:359`). Guests get
   `<ip>/32` + `default dev eth0`, no gateway
   (`scripts/build-rootfs-ubuntu-24.04.sh:115–117`). Postgres
   `listen_addresses = '10.255.255.1'` requires that address to be
   local; if it is not, `init` fails
   (`server.ex:133–146`) and `:rest_for_one` takes Sites down with it.

   The citation is wrong. `systemd/forgejo-runner.service:12`
   `FORGEJO_HOST_URL=http://10.255.255.1:3000` is a **host** unit env
   var, not proof guests reach a host bind. Elixir’s own runner default
   is `http://127.0.0.1:3000` (`config/config.exs:151`). The address
   guests are told to use for the host API is a **different** IP:
   `:host_api_ip` default `"10.200.0.1"` (`lib/mjolnir/vm.ex:1843`) —
   also inside the guest pool, also unreserved, also unassigned in
   `scripts/bootstrap-host-ubuntu.sh`. No dummy/`lo`/`ip addr add` for
   either address exists in this repo. Binding postgres to an IP the
   host does not own is a first-boot wall; “fixing” it with `*` is how
   the public NIC opens.

2. **MODIFIED delta renames the living requirement, so fold cannot
   replace it.** Living text is `### Requirement: Host sidecar is
   control-plane only` (`openspec/specs/buzz-local-client/spec.md:76`)
   and SHALLs NOT hold a tenant app database. The change writes
   `### Requirement: Host sidecar is control-plane by default`
   (`openspec/changes/add-host-sidecar-tenant/specs/buzz-local-client/spec.md:3`).
   OpenSpec-lite: “MODIFIED pastes the entire living requirement, then
   edits. Fold replaces that block wholesale”
   (`openspec/AGENTS.md:33–34`). A renamed block is not a replace. After
   fold the living spec would keep the old SHALL NOT **and** grow a
   MAY — the reopen fights itself.

3. **`Tenants.ensure` is not specified enough to implement without
   guessing.** Spec + design give identifier regex, `CREATE DATABASE`
   + LOGIN owner, “no CONNECT on `mjolnir`”, idempotent, don’t reuse
   `mjolnir_sites`. Missing, and load-bearing:

   - **Password origin and escrow path.** Design says
     `` `/var/lib/mjolnir/<app>-secrets.json` / SecretStore ``
     (`design.md:67`). Code reads
     `/var/lib/mjolnir/deploy/secrets/<slug>.json`
     (`lib/mjolnir/deploy/orchestrator.ex:404–413`). The docs path is
     a stale worked example (`docs/guide/deploying-an-app.md:172`).
     An implementer following the ADR writes a file deploy will never
     inject.
   - **`PUBLIC` has `CONNECT` by default.** `REVOKE CONNECT ON DATABASE
     mjolnir FROM hypersigil` does not stop a LOGIN role from connecting;
     `PUBLIC` still holds `CONNECT` on every database, including other
     tenants. Bootstrap only *grants* CONNECT to service roles
     (`lib/mjolnir/postgres/bootstrap.ex:161`); it never revokes PUBLIC.
     The spec scenario “cannot connect to `mjolnir`” fails unless PUBLIC
     is revoked and control-plane roles are re-granted. ADR item 6
     “cannot see other tenant databases” is the same footgun on the
     tenant DBs themselves (`public` schema CREATE is also PUBLIC).
   - **When ensure runs.** Not on bootstrap (correct — rest_for_one).
     Not a config list. Not a host command name. First tenant
     `hypersigil` has no declaration site. Tenant roles must **not**
     enter `pg_roles` / `pg_ident.conf` or the BEAM peer-maps into the
     shop (`server.ex:267–277` maps every ident user × every role).
   - **`pg_hba` host lines.** Today `pg_hba_conf/1` is Unix-socket only
     and is overwritten every boot (`server.ex:258–264`). “No `pg_hba`
     match” for unprovisioned guests is a slogan until the actual
     `host … scram-sha-256` line is written (per-DB vs `all`, overlay
     CIDR vs `0.0.0.0/0`). `initdb --auth-host=reject` (`server.ex:207`)
     only matters for the first cluster; every subsequent boot already
     clobbers `pg_hba`.

4. **Backup “off BTRFS” is vacuous against the threat the design
   named.** Postgres data is already *not* on a VM subvolume
   (`pg_data_dir: "/var/lib/mjolnir/pg"`, `config/config.exs:161`;
   BTRFS root is `/var/lib/mjolnir/btrfs`). Spec scenario “dump exists
   off `@vms`” (`specs/host-postgres/spec.md:69–73`) is satisfied by
   writing next to the data dir on the same disk. Design Decision 4
   says “a host disk loss wipes the shop” and cites
   `forgejo-backup.timer` — that unit ships to Backblaze B2
   (`systemd/forgejo-backup.service`), not to a local path. Cadence,
   destination, dump encryption (shop catalog is source of truth, not
   a Sites index), role recreation on restore, and **exit** (Duke can
   `pg_dump` the tenant over the same TCP path and leave with the
   catalog) are unstated. Cutover-safe does not need this dump.
   Host-disk-safe and exit-test both do.

5. **In-flight `add-buzz-local-runtime` SHALL still re-forbids this,
   and the amend is “not a box.”** PENDING delta:
   “Stateful production workloads that need concurrent writers SHALL
   run real Postgres inside their own VM, not on the host sidecar”
   (`openspec/changes/add-buzz-local-runtime/specs/buzz-local-client/spec.md:68–69`).
   Proposal out-of-scope and `tasks.md:11` defer the amend until after
   advise accept. Accepting this change while that SHALL remains
   PENDING is two in-flight truths. An `act` on the runtime change
   first puts the hotel back under a SHALL NOT. The amend is a docs
   edit on a file this change already named — it is owed here.

## What is solid

- Decision 1 (one postgres, two classes) matches the cutover problem
  and does not turn `mjolnir_sites` into a migrator.
- Decision 2 correctly rejects virtiofs of the Unix socket
  (`extra_mounts` is the old spec’s named hole).
- `listen_addresses` SHALL NOT be `*` or empty; public NIC SHALL NOT
  accept 5432 — the *intent* is right. The mechanism is not specified
  enough to survive first boot.
- Secrets-out-of-snapshots requirement matches the existing
  `:managed` LUKS → `/run/mjolnir/secrets.env` tmpfs path
  (`lib/mjolnir/deploy/runtime.ex:141–148`).
- Buzz community events stay off this process; that half of ADR 0002
  item 7 does not move.
- Out of scope is disciplined (Redis, uploads, multi-host, every-app
  hotel, Distributed Erlang).
- Existing tests already pin today’s policy (`server_test.exs:76`
  `listen_addresses = ''`; bootstrap has no DDL for `mjolnir_sites`).
  They will have to move; at least they exist.

## Implementer gaps (after the amend — not a license to act now)

- `postgresql_conf/1` / `pg_hba_conf/1` are the whole TCP surface and
  are clobbered every start. Exact `listen_addresses` line, exact
  `host … scram-sha-256` line, `password_encryption`, and “fail if
  bind IP missing — never fall back to `*` / `0.0.0.0`” must be in
  the spec, then in those two functions. Update
  `test/mjolnir/postgres/server_test.exs:76`.
- Overlay IP must be created (dummy or `lo`) **before**
  `start_managed/1`, and `Network.allocate_ip/1` must refuse it
  (and `10.200.0.1` if that remains `:host_api_ip`). Pick **one**
  host-from-guest address; do not invent a third.
- Public-NIC scenario must not hardcode `45.76.77.97`
  (`specs/host-postgres/spec.md:32–47`). Assert “not listening on
  the default-route NIC / not `0.0.0.0:5432`”. The current scenario
  is unrunnable in the `/tmp` postgres test harness.
- `docs/security/host-hardening.md:67–70` still says socket-only and
  “derived data only”. This change makes both sentences false.
- Tenant `pg_dump` from the guest (same `DATABASE_URL`) is the exit
  path. Host timer dump is disaster recovery. Both are owed; only
  the timer is mentioned.
- Do not put tenant roles in `pg_ident.conf`.
- `max_connections = 100` is shared. Not a blocker; don’t ignore it
  when Medusa + Sites sit on one Port.

## What the amend must do

Rewrite Decision 2 as: the host overlay bind IP is a **reserved,
assigned** address, excluded from `allocate_ip/1`, created in
host bootstrap, up before postgres starts. Reconcile with
`:host_api_ip` (`10.200.0.1`). Stop citing
`forgejo-runner.service` as evidence of a guest→host bind this
tree does not create.

Keep the living requirement **name** `Host sidecar is control-plane
only` and edit the body (MAY declared tenant DB; SHALL NOT Buzz
log; default guests have no path).

Specify `Tenants.ensure`: generate password; write
`DATABASE_URL` into `/var/lib/mjolnir/deploy/secrets/<slug>.json`
(or change deploy — don’t invent a third path); `REVOKE CONNECT …
FROM PUBLIC` on `mjolnir` and on every tenant DB, then re-grant
control-plane / owner; invocation (operator command *and* declared
list); `pg_hba` lines; tenant roles stay out of `pg_ident`.

Pin backup to an off-host sink in the `forgejo-backup` shape (B2 or
equivalent), not “off `@vms`”. Restore recreates role + database.
Name `pg_dump` over tenant TCP as the exit test for the catalog.

Turn the `add-buzz-local-runtime` amend into a checkbox on this
change and edit that PENDING sentence now so it does not re-forbid
declared tenants.

Then re-advise. Do not `act` on the hotel until a later advise is
`accept` or `accept-with-nits`.
