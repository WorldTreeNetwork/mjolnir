All three send-back blockers are closed. `design.md`, the spec
delta, and ADR 0002 now say the same thing on every load-bearing
sentence. No new blocker. Remaining items are implementer gaps that
belong to later `act` nodes (`nod-identikey-admit`,
`nod-mailbox-control`), not to this architecture write.

## Steelman against

Same as 2026-08-17: attestation + epoch vocabulary is ceremony while
every `deliver_message/3` caller lives in one BEAM; a process
allowlist would hold I5 today. The docs now concede this explicitly
("a conforming Mjolnir-local evaluator is permitted — v1 may be a
process allowlist"), which is the right way to hold the tension: buy
the vocabulary now, defer the machinery.

## Tradeoff

Fail-closed before `pending_messages` still converts evaluator
outage into silent drops for non-Buzz VM-to-VM senders, who today
get durable queue-then-restore. Accepted in the prior review; the
spec's "Junk does not thaw" scenario makes it deliberate. Restate it
in the `nod-identikey-admit` packet so the implementer doesn't
"fix" it back.

## Findings

None at blocker or should-fix severity.

## Nits (implementer gaps — do not amend for these)

1. Default verdict for an *authenticated* `mj message` to a
   non-Buzz dormant VM is unstated. Today's behavior (queue +
   restore) presumably becomes an allowlist-pass; say so in the
   `nod-identikey-admit` packet.
2. Guest-originated vsock wake: which proxy stamps the attestation
   is deferred to `nod-mailbox-control`. Fine — just keep it there.
3. Replay/TTL semantics inside one lifecycle epoch are unspecified
   (`nod-identikey-admit`).
4. Precedence when `restart_policy: :never` and
   `secrets_mode: :persistent` both apply to `signal_done` (carried
   from prior review's gap list).
