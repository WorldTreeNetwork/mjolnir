# Gateway: send-back, bounded corrections

The revised architecture is accepted in substance: exact-token connection reuse, assess on every new operation, trusted configured-origin `/admit`, verified relay TLS, fail-closed key reload, owned DELETE and forwarding-stop acceptance. ADR 0020 records those choices adequately. Do not reopen per-leg versus per-token, root-marker identity, viewer bypass, or immediate DTLS notification.

## G1/G3: `/admit` must actually finish admission (high)

`design.md:40` stops at step 6; operation/grant matching is step 7 and expiry recheck is step 8. A subscribe-only credential can therefore obtain a publish admission, contrary to the spec and browser's before-camera promise. Stop after all non-media checks; validate an explicit publish/subscribe operation and canonical broadcast, and bind the result to that request. Test denied self publish and denied named-peer subscribe with zero dial/SDP/media side effects.

The route `POST /admit` and browser body `{operation,broadcast}` have no URL room segment, yet step 5 requires one. Define its room source (the independently expected full root is sufficient for this no-room-URL route), and retain URL-room checking for the actual media routes. Use the existing exact room classifier grammar, including `[A-Za-z0-9_-]{1,64}` (`room_class.ex:10–21`), rather than the weaker nonempty/non-dot grammar at line 45.

Loader parity also needs `key_file_trusted`, not only `load_verify_keys`: `native/mjolnir_relay/src/lib.rs:313` checks ownership/mode separately; the latter only parses/validates key contents. Name that trusted-file check for initial load and reload. No JWKS service, new authorizer, or token-level revocation is requested. Routine key removal and invalid reload must refuse new operations even on a pooled connection; admitted legs retain their original exp. Reassessment at media POST remains the necessary stale-preflight backstop.

## G2: distinguish candidate failure from whole-token expiry (high)

`design.md:78`, proposal's expiry journey, the spec's expiry scenario and the task all require another leg of the *same* token to survive expiry. That contradicts line 60 and the living relay contract. Change the expiry assertion to all same-token legs stopped, other-token legs unaffected. Use a setup timeout strictly before exp to prove candidate-only cleanup while a same-token incumbent survives.

The five-second deadline is created *after* relay dialing (`design.md:53–54`). Start it before pool acquisition/dial and bound that await too, including cancellation and relay death. Set a deterministic mapping when the outer deadline wins the catalog timeout: currently the table says 503 while the spec requires 409 for catalog absence by the deadline. Expiry always wins over a retryable catalog classification.

The at-most-one connection rule is good; implement/test a single-flight dial with owned reservations, not a lookup/dial/insert race. Include simultaneous same-token POSTs, last-release versus new-acquire, cancelled setup, natural runner completion and relay death. The registry must own a cancellable runner/handle once `Response::run(self)` consumes the Response (`server/mod.rs:43`), release each hold exactly once, and remove entries on normal completion as well as DELETE. A detached task must not survive request cancellation or a failed answer write. These are realization tests of the chosen model, not another architecture choice.

Repeat DELETE after deletion needs a tombstone policy: retaining token bytes and ids forever grows with total historical calls, even after exp. Specify a finite retention horizon (for example exp plus a short retry grace, then 404), storing only necessary ownership data and no media resources. This small boundedness amendment is sufficient; no distributed tombstone store or quota system is required.

## G4: test accepted video, not presence of a video line (high)

`design.md:28,56` and the normative requirement use “no video m-line.” Pinned SDP rendering preserves rejected m-lines with port zero (`rs/moq-webrtc/src/sdp.rs:166–177`); such an answer still contains `m=video` and would slip through as silent audio-only 201. Match the proposal's stronger rule: when video was offered, require a usable accepted video section, not port 0/inactive rejection. Exercise the actual pinned rejected answer and drop the unrun Response. Catalog errors may occur before any Response exists (`server/whep.rs:158–202`); cleanup releases the candidate hold in both cases.

## HTTP and integration details to retain

Configured origins, exposed Location, no credential redirects and single parsing are sound. Check backslash after percent decoding as well (`%5c`), malformed escapes, encoded dot segments, and bounds before moq I/O. Pin/moq `Path::new` permits an empty root and some escapes; it is not alone the stricter broadcast validator. Its byte bound is 4096; namespace depth is at most 32, including the effective root. Assert the admitted string equals the string passed to moq. These parser tests fit the existing G4 task, without inventing a new naming scheme.

Coordinate browser B4: `/admit` currently returns `room_not_open` before root equality and never yields a protected admitted root, while the browser promises `unexpected_root`/`open_refused` from a 200. Resolve the cross-contract error mapping explicitly; do not fake successful protected admission merely to satisfy browser mocks.
