# Independent gateway CODE review — 4169315

**SEND-BACK.** Reviewed `4169315c55ee49b160deaafe5182420a690dc6ee`, implementation delta from `4bcc87f43bb90ac4dd3d3830052be70af9539122`, and the entire resulting gateway. Contract: accepted `7f9195cb` / review `8e65b23d`, design D1–D8, spec/tasks, ADR 0020, open-room identity rules and `.13`/`.15` bead history. The reader did not author the product. No product edits, remote jobs, deployment, closure, fold, or nested delegation. Baseline admission defects are included because this review covers the complete product, not only newly introduced lines.

## Required repairs, in priority order

### R1 — P1: own reservations and clean up every runner exit

`native/mjolnir_relay/src/edge.rs:216–231,254–266,514–515`; `native/mjolnir_relay/src/moq_session.rs:26–33`.

After `acquire`, negotiation awaits with no drop guard. Cancelling that future leaves its ref and relay link alive without a session id. Once running, the task only awaits `response.run()` and discards its result. `reap_runners` removes finished handles but never the corresponding session/ref/link. A browser that fails ICE, disconnects, or finishes naturally leaves stale ownership until a sweep or DELETE. `Shared::dead/closed` are never called: a closed relay link remains eligible for reuse, and relay death does not cancel all associated WebRTC runners.

Repair with a per-attempt owned reservation that releases exactly once on drop until transferred to the registered runner. Install completion cleanup before starting the runner; remove only the same session generation, release its hold, and retain ownership metadata as required by R8. Watch relay closure once per connection generation and cancel/remove that generation's sessions and candidates. Do not hold the pool mutex while awaiting completion. Test cancellation after acquisition, normal ICE timeout, relay death with multiple same-token legs and a different-token control, and reuse after death.

### R2 — P1: retain one setup deadline and make expiry win all exits

`edge.rs:209–250,384–438,449–475,483–488`; `moq_session.rs:68–81`; `src/bin/mjolnir-edge.rs:38–42`.

The deadline is created before acquisition but discarded after it. WHIP gets a fresh five seconds; WHEP gets twelve (the pin has its own five-second catalog bound). Neither negotiation races token expiry or relay closure. Success has no expiry/deadline/closed recheck before registering and returning 201. Codec rejection returns 409 without the expiry override. Dial failures return 503 directly; `timeout_error` looks up expiry only in `holds`, although a first dial/follower has no hold yet. Thus expiry during initial acquisition can be 503. `follow` also prioritizes a ready result over its deadline without a subsequent expiry check. Unix-second truncation can extend the nominal expiry deadline by almost a second.

The binary only sweeps every five seconds. Relay enforcement may stop relay traffic promptly, but it does not implement timely edge resource teardown, nor prevent a pending setup from registering after the sweep removed its hold. A successful late registration then has no hold for a future sweep to find.

Carry an absolute deadline and authenticated expiry through acquisition and negotiation. Race them and relay closure, use one finalizer with expiry first on every success/error exit, and schedule whole-token expiry independently of key reload. Classify the current setup phase to distinguish pre-expiry catalog 409 from other setup 503. Reject publication of a result after its connection generation was removed. Candidate-only pre-expiry timeout must preserve incumbents; expiry must remove every same-token leg and leave other tokens untouched.

### R3 — P1: failed answer delivery has no cleanup owner

`edge.rs:254–266,863–870`.

`Response::run` is spawned before the HTTP response is constructed. The answer is an ordinary `Body::from(String)` with no ownership/abort hook. Dropping the returned response or failing its socket write leaves the runner and hold registered. The client cannot DELETE an id it never received. A real-Router probe negotiated an actual 201, dropped its body without consumption, and observed runners=1/sessions=1/refs=1. This proves the missing response-drop owner; an actual socket-write failure with an incumbent remains a required regression. This is distinct from cancellation while negotiating (R1).

Return an owned pending-session response/transaction and integrate its transfer with HTTP delivery; cancellation/delivery failure must drop the response or cancel the runner and release only that candidate. Start media only at the specified queued-response boundary. Test dropping the HTTP response before consumption and a real client disconnect during delivery, with an incumbent on the same token. Merely retaining a JoinHandle is insufficient.

### R4 — P1: successful shared dial does not reserve waiting attempts

`edge.rs:425–432,455–464,500–510`.

The leader creates `refs=1` and sends `Ok(())` to waiters. Waiters acquire their refs only when scheduled later. If the leader rejects its codec/SDP or releases its last session first, the hold/link is removed and a valid waiter receives `setup_failed`. A new acquisition can create a replacement generation before that waiter resumes; the waiter then increments whichever hold happens to occupy the token key, rather than the connection it joined.

Give each follower an owned reservation tied to the flight/connection generation before notifying it, or atomically retry acquisition when its generation disappears. Cancellation must release the follower reservation and remove/bound stale waiter slots. The leader-cancellation guard is useful before acquisition, but does not solve this race. Add controlled leader-rejection/waiter, leader cancellation, waiter cancellation, and last-release/new-acquire interleavings; the current sequential delete/redial test is not that race. The new `a8e6b9b7/timeout.txt` trace is consistent with FlightGuard broadcasting SetupFailed when the one-second leader is cancelled: the later waiter ends at that same instant, without using its remaining setup budget or becoming leader. That timing alone does not prove a leaked ref or a duplicate dial; the rejected-leader reproduction proves the missing waiter reservation independently.

### R5 — P1: HTTP decodes the path before the canonicalization barrier

`edge.rs:822–839,685–705`.

Axum `Path<(String,String)>` already percent-decodes captured values. `/whip/standup/alice%2fcam` reaches `canonical_broadcast` as `alice/cam` and passes; `/whip/standup/%2561lice/cam` becomes `%61lice/cam`, then the gateway decodes it again to `alice/cam`. `/admit` given the original spelling rejects it. The direct parser unit tests miss this HTTP behavior. This does not demonstrate a cross-tenant grant escape, but violates the agreed single-decoding identity boundary and allows forbidden wire spellings to reach dial.

Extract the raw broadcast remainder from the original URI, reject encoded separators/malformed escapes there, decode exactly once, and use that single validated string for grant matching and moq. Keep the URL room/root check. Test both media routes through the real Router, including `%2f`, `%252f`, `%5c`, encoded dots, `%2561`, byte/depth limits and a valid encoded character; assert the actual path delivered to moq.

### R6 — P2: missing broadcasts map to the wrong client-visible status

`edge.rs:232–244`; `moq_session.rs:78–81`; pinned `native/vendor/moq-webrtc/src/server/whep.rs:226–240` and `src/error.rs:32–58`.

Errors are flattened into Display strings and checked for `NotFound`, `catalog`, or `NoRenditions`. The actual missing-route error is `moq error: unroutable`; it becomes 503, although absent broadcast is 409 `not_started` before subscriber expiry. Searching for enum variant capitalization is not reliable for Display strings. A relay-close failure must also remain distinguishable from an absent broadcast.

Retain typed negotiation/transport errors until the HTTP boundary and map `Moq(NotFound|Unroutable)`, catalog timeout/closure and no renditions deliberately, subject to R2's expiry/relay-close precedence. Test a valid viewer of a missing publisher separately from an expired viewer. The new `a8e6b9b7/expiry-clock.txt`, `expiry-viewer.json` and `expiry-edge-lines.txt` confirm precisely this distinction: an expired requester gets 403 bad_token with no new relay session, while valid Bob receives 503 from unmapped unroutable after publisher expiry. This proves R6, not an expired-requester admission failure.

### R7 — P2: configured origin and admission-response contracts are absent

`edge.rs:630–649,786–819`.

Every origin receives `Access-Control-Allow-Origin: *` while Authorization is allowed. There is no origin-list configuration or same-origin-only default, and no preflight max-age 600. Successful `/admit` lacks `Cache-Control: no-store`. Axum JSON rejection escapes the promised error envelope: missing fields yield 422 text, malformed syntax yields a framework rejection, and extraction/operation parsing precedes the specified bearer/profile checks. `Location` is correctly relative and exposed on successful media responses.

Add the configured allowlist, echo only an allowed origin with `Vary: Origin`, default to same-origin access, and set preflight max-age. Set no-store on successful admission. Handle extraction errors explicitly as D2 `400 {"error":"bad_request"}` and preserve D3 admission precedence, including absent bearer with malformed operation/body. Remove the global `dials()` equality debug assertion: another concurrent media request can legitimately increment that counter and panic an unrelated `/admit` in a debug build.

### R8 — P2: tombstones are neither complete nor time-reaped

`edge.rs:192–204,532–550,574–616`.

A different bearer DELETE of a retained tombstone returns 404 rather than the contracted 403. Expiry removes active ids without retaining ownership, so the owner gets 404 during exp+30s. Tombstones are only purged on another DELETE; the regular sweep does not reap them, so an idle service can retain them indefinitely after the horizon. Natural-completion cleanup is absent entirely (R1).

Use one id-finalization path for DELETE, expiry and completion: retain only digest/id/exp+30s, enforce owner 204 / foreign 403 until expiry of the tombstone, then 404, and reap on the periodic lifecycle timer. Do not retain tokens, runners or links there. Test the horizon without issuing another DELETE to trigger cleanup.

### R9 — P2: verifier ceiling and drain policy cannot be configured correctly

`edge.rs:151–157,186–188,280–289`; `src/bin/mjolnir-edge.rs:22–50`.

The edge always uses `DEFAULT_MAX_TTL` (3600); the binary never reads the relay's configured ceiling and offers no constructor configuration for it. A lower ceiling can therefore pass `/admit` and fail only at the relay, while a higher legitimate ceiling is refused locally. `close_admissions` is the only close switch; the next successful key reload unconditionally reopens it. There is no edge drain handler that closes connections as D1 requires.

Pass the configured relay ceiling into the snapshot, validate it at startup, and keep drain state distinct from key health (`open = keys_ok && !draining`). Add the emergency drain operation/signal and connection teardown. Test lower/higher ceilings, invalid-key reload preserving existing sessions, good reload recovery, and good reload while draining never reopening admission. Initial and repeated trusted-file/key loading itself is correctly wired.

### R10 — P2: product WHIP remains uncapped

`moq_session.rs:64–68`; pinned `server/whip.rs:114–123,211–225`; pinned `moq-mux/src/ingest.rs:45–52`.

`Request::new` defaults `ingest.rate` to `None`. Product code only sets `keyframes`; it never sets a rate limit. Thus the `.13` recorded ingest-cap-on default (2.5 Mbit/s) is not adopted. This is separate from the out-of-scope per-owner quotas. Set the agreed ingest limit before accept and exercise TIAS/REMB plus termination of an over-cap sender. Preserve the accepted keyframe trial policy: it is enabled here with floor 1s, period 2s, loss/join on, ratio 4, saturation false. No keyframe regression is alleged.

## What is sound, and what this review does not claim

The real HTTP media route now uses `open_session`, actual verified relay dialing, and actual pinned `whip::accept`/`whep::accept`; it no longer returns fabricated SDP. The mock dial switch and fabricated-answer `attach` helper remain compiled/public in the library (`edge.rs:87–91,178–180,347–381,492–495`); move these behind test-only scope when consolidating tests onto production ownership logic. They are not enabled by the shipped binary, so this is not a claim that observed playback used a mock.

Every routed media operation calls the shared `admit` before SDP negotiation or relay dial, even for pooled tokens. It snapshots keys, calls the existing `assess` profile/grant verifier, classifies literal canonical open roots, rejects protected/wide roots before expected-root comparison, compares the full expected root byte-for-byte, and checks the operation grant. `/admit` does no dial. Canonical byte/depth bounds and port-zero/media-level-inactive video checks exist; the HTTP parser composition is R5, and pinned rejected-video outcomes still need production-path tests.

TLS explicitly sets insecure false; custom PEM roots disable system roots, and absent custom roots use the pin's verified trust path. The existing `edge_tls` negative case uses malformed PEM (`not a cert`), not a valid foreign CA/hostname rejection. Add those two cases before calling that TLS matrix complete. No bearer log leak was found in the exercised gateway calls: current media logging prints header names, and the pin's connection logs use a redacted Endpoint. `Checked` derives Debug over raw token bytes; remove/redact that unnecessary exposure. No claim is made about exhaustive dependency error-string sanitization.

Pinned `Response::run(self)` consumes its owner. Its `AcceptedSession` unregisters the media server on drop; `Server::terminate` removes a sender and signals that runner, and WHIP may linger after a normal terminate. The edge's terminate followed by task abort avoids waiting out that linger and is a reasonable stop mechanism. It does not repair the separate gateway maps/refcounts or answer-delivery ownership. Immediate browser DTLS close notification is not required and is not a finding.

## Evidence gaps and safe next step

The original Arch record establishes a real Mint-issued open-token Chromium WHIP → relay → WHEP path with 279 decoded frames, matching colors and approximately 439 Hz tone. During review the builder committed diagnostics `d2722738` and `5c884737`, with **no product delta**. I read the new `evidence/a8e6b9b7` hashes, playback, expiry, pool, timeout and Ubuntu records. They establish playback of the current a8e6b9b7 binary at both early (~2s) and late (~8s) joins: matching colors, 439 Hz tone, and decoded 640×360 video. This closes the earlier log-only-binary replay gap. The prior tone-loss observation did not repeat; it remains historical evidence, not a newly established code defect or reason to reopen accepted keyframes. The 1280×720 fixture and later publisher geometry do not make this a 720p playback proof.

The expiry traces distinguish a genuinely expired requester (403 bad_token, no new relay session) from a still-valid Bob viewer after publisher expiry (503 setup_failed / unmapped unroutable: R6). An already-running WHEP ends with unroutable at publisher expiry. `legs=1 sessions=1 runners=0 links=1` after token drop, and the later Alice DELETE counts, retain an **other-token** link: those counts alone cannot prove erroneous same-token retention or whole-token teardown failure. They are consistent with R1's stale completed-viewer entry; the isolated real ICE-timeout probe independently proves that defect using one token, zero surviving runners and refs/link/session still present. Do not label a live different-token link a leak. The five-second blackhole dial and simultaneous-leader/waiter timings verify the dial bound, not the end-to-end negotiation/delivery deadline or all cancellation interleavings.

The Ubuntu image record proves only that an Arch-built ELF loads against that image's libc. No Cargo/rustc build occurred there. **Ubuntu 24.04 build of this binary remains owed.** Replay the repaired product hash after R1–R10; do not reuse either Arch run as proof of future code.
