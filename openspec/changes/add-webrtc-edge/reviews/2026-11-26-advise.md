# Gateway: send-back

The full-assess/open-root/expected-root direction is sound, and every leg must remain relay-authorized. The contract is not yet an executable boundary for the browser and session lifecycle.

## Independent source-first constraints

Before reading the new designs/tasks, I read the proposals' Why and existing relay/room-auth and call-E2EE contracts, then `native/mjolnir_relay/src/lib.rs` and `lib/mjolnir/relay/{mint,room_join,room_class}.ex`. These are the concerns against which I compared the designs:

1. Authenticate the exact credential, never decoded claims or caller-provided success.
2. Preserve the complete relay profile and grant validation, not just signature/expiry.
3. Keep the invitation identity independent of authenticated identity and compare exact full roots.
4. The server treats that expected root as untrusted input; equality narrows authority, never creates it.
5. Preserve publish/subscribe confinement and relay authorization on every media path.
6. Finish admission before media side effects, including across renewal and asynchronous waits.
7. Scope teardown to owned resources; a failed candidate must not destroy a valid incumbent.
8. Keep expiry, routine rotation and emergency revocation distinct.
9. A browser needs an authenticated trust source before its camera/PC gate can mean anything.
10. Connection reuse trades lifecycle complexity for fewer handshakes/sockets; never pool across credentials to save cost.

The accepted open-room path architecture is not reopened. ADR 0019 and the accepted `82078ec7` path contract establish the identity rule; `reviews/2026-11-26-code-review-2.md` accepts only the unwired comparison seam, with precise integration obligations. `RoomJoin.check/4` is neither a verifier nor a browser.

## Required amendments, in priority order

**G1 — high: resolve connection ownership against the recorded steer.** Proposal “Each accepted offer opens a relay session” and spec “Each WebRTC leg uses its own relay session” contradict `.13`'s recorded owner steer, “one relay connection per token.” Using each leg's bearer does not require a separate connection for every leg. Restore per-exact-token reuse, with no sharing across token/root/authority, new admission on each operation, a refcount/ownership rule, last-user close, and whole-token closure at expiry/relay termination. A replacement credential owns a separate connection. If per-leg connections are deliberately retained, record an explicit amendment to that steer and its cost; the general build grant does not itself document that choice. This is the genuine unresolved architecture scope decision, not a request for permission to implement routine details.

For N full-mesh WebRTC participants there are N² media legs. The spike also creates N² relay QUIC connections; per-token reuse can reduce those to N for one token per participant, without reducing WebRTC leg count. Renewal overlap temporarily adds resources. Claim 7's 8-WHEP ~47% of one M1 Max core is a mixed pipeline observation, not an isolated connection-cost benchmark or a Linux capacity claim. Keep per-owner limits/metering on `.4` and do not claim them implemented. If connections are reused, a new leg must still respect current key/drain admission; an old valid connection is not permission to bypass new-admission refusal.

**G2 — high: make setup and teardown a bounded transaction.** D3 step 8 checks expiry before relay/catalog/SDP awaits, but step 11 can return 201 after expiry. The spec forbids this; tasks do not demonstrate it. Bound setup by expiry and a setup timeout, race it against relay closure, recheck immediately before returning 201, and drop every candidate resource on refusal, timeout, cancellation, or answer-delivery failure. Do not keep a registered mux session after a 409. Pin a session registry tying id to its credential and resources; specify DELETE authorization (exact admitting bearer is the simplest reading of D2), repeat/unknown-id behavior, and cleanup after normal close as well as DELETE. The spike's unauthenticated `end()` is not the promised token-bound delete implementation. A failed new POST keeps the incumbent; cleanup never stops another leg using a shared relay connection.

Source evidence: pinned `server/whep.rs:158-202` resolves the catalog, creates/registers a media session and returns `Response`; `resolve` has a five-second catalog bound. `server/mod.rs:31-110` exposes answer/id and `run`, unregisters on drop and treats DELETE linger separately. No public explicit DTLS-close method is exposed by `Response`. Spike claim 4 stops traffic at expiry but browsers notice 6–7 seconds later; it does not prove immediate DTLS close notification. State whether acceptance requires no further media/closed server association or immediate browser notification. For the latter, name a feasible API/patch and demonstrate it; do not count dropping the runner as evidence of an outbound close_notify. Expiry and emergency closure must bound lingering content too.

**G3 — high: complete the browser admission dependency and trust configuration.** See the companion browser review B1. The present gateway has no non-media admission endpoint and the mint has no verification-key bootstrap. Recommended minimal amendment: a trusted HTTPS preflight that invokes this same full admission path, with exact token, expected root, operation and broadcast bound to its result; no relay dial or SDP side effect. WHIP/WHEP must repeat admission at use, not trust a prior JSON result. Alternatively specify authentic public JWKS delivery and the entire browser policy. Keep trusted page/gateway/relay origins in configuration, never derive token destinations from untrusted invitation URLs. The gateway must verify the relay's TLS identity; the spike `client()` defaults to insecure verification unless EDGE_RELAY_VERIFY=1 and cannot be copied as a product default.

`assess` accepts an explicit max_ttl and does not itself load keys or observe draining/keys_ok (`lib.rs:215-246`). Use the configured relay ceiling, not the spike's hardcoded DEFAULT_MAX_TTL. Define one coherent request snapshot of accepted key set and availability state; retain original authenticated root. Loader parity includes public-only keys, allowed algorithms, unique/nonempty kids, trusted file ownership and invalid reload fail-closed behavior (`lib.rs:59-94,313-340`). Routine rotation retains admitted sessions until exp; removed keys reject new admissions after reload, and emergency restart/drain closes each leg through its relay connection. Test rotation, invalid reload, emergency closure, and expiry during setup. There is no per-user kick or token-level early revocation.

**G4 — medium: close the HTTP/path and error contract.** D2 lists allowed headers, not allowed origins, preflight methods, or exposed response headers. Pin allowed page origins (or same-origin hosting), POST/DELETE/OPTIONS, Content-Type/Authorization/X-Mjolnir-Root, and exposed Location. No credential-bearing redirects to an arbitrary origin. Return typed bodies for missing/bad token, room/root/path refusal, catalog absent, codec unavailable and transient relay/setup failure. Define path parsing once, before grant matching; reject empty/dot/escape forms and test encoded slash, percent and backslash inputs against the exact path passed to moq. A narrow viewer grant must also constrain catalog sibling references/rendition changes via the relay-scoped consumer, not merely the top-level WHEP address. Invitation path strings are data, not request URLs.

The pinned WHEP API internally resolves catalogs and can return a 201 answer with video rejected (Firefox AV1 spike). Its private source resolver is not an exported preflight API. An implementation can inspect the negotiated answer and drop the unrun Response on codec miss, or add a bounded helper; specify that “no session” means no surviving/running media session, since catalog resolution itself needs the authorized relay connection. Apply catalog matching to WHEP; WHIP ingest has no pre-existing source catalog. Identify error mappings for CatalogTimeout, absent broadcast and no renditions, and forbid publishing an SDP answer on failures.
