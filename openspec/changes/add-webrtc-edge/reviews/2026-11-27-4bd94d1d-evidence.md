## Diagnosis: the 503 was not a missing catalog

`168de10e` posted `v=0` as the WHEP body for `/whep/r1/missing/cam`. That is not a catalog lookup.

`moq_session::whep` calls `moq_webrtc::whep::accept`. `accept` runs `sdp::parse_offer` before `resolve` (`native/vendor/moq-webrtc/src/server/whep.rs`). `v=0` fails there as `Error::InvalidSdp`.

`map_webrtc` (`native/mjolnir_relay/src/moq_session.rs`) maps only `CatalogTimeout`, `CatalogClosed`, `NoRenditions`, `NotFound`, and `Unroutable` to `SetupFault::Catalog`. Every other error, including invalid SDP, becomes `SetupFault::Other(text)`.

`Edge::classify` maps `Catalog` to `409 not_started` and every remaining fault to `503 setup_failed` (`edge.rs`, `classify`). Expiry is still checked first.

So a still-valid token plus `v=0` is specified to be `503 setup_failed`. It never reaches the absent-broadcast path. The HTTP body has no inner fault; the edge does not log `SetupFault`.

The real offer is the contract case (design D8, spec: WHEP that cannot obtain a catalog before expiry is `409 not_started`). The earlier `503` does not contradict it.
